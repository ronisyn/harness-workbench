# 权限与沙箱（服务器版）· harness 三层映射 v1（5.6 交付件）

> 目标：把 harness(3080) 的"文件策略分层 + 单次升级审批"语义映射到 RW 服务器环境，
> 针对服务器特点调整（路径体系 /srv、MySQL、systemd、多用户渠道），不一概照搬本机模型。

## 1. 层级映射（harness → RW 服务器版）
| harness | RW 会话级 | 服务器版语义（与 harness 的差异已标注） |
|---|---|---|
| read-only | permission=read | 只读：read/list/find/grep/db_query/web 等。**差异（更严）**：本地路径限定 /srv/rw-workspace（limitPath），防服务器上读 /etc、密钥、他人目录；harness 本机版无此全局风险面 |
| workspace-write | permission=write | 工作区读写：write/edit/append/mkdir/copy/run_test/skill_save/kb 等；路径限定工作区；**差异**：写平台代码/DB/系统一律拒绝（服务器上工作区≠平台目录，天然隔离，无需 harness 的 cwd 技巧） |
| danger-full-access | permission=full | 全服务器：平台代码、MySQL、systemd、任意路径。等同 harness danger 级 |
| ask/never（审批策略） | permission=guard | guard=full 级能力 + **受控工具审批门禁**（GUARDED_TOOLS：delete_file/db_write/git_pull_push/reload_platform/run_command/kill_process/set_limits/plan_mode/exit_plan_mode） |

## 2. 单次升级审批通道（= harness "升级该次操作"）
- guard 会话中调用受控工具 → createApproval 弹确认卡（前端红卡：批准/拒绝/超时）；
- **批准仅对该次调用生效**（会话权限不提升）——与 harness 单次升级语义一致；
- 无人值守（driver/定时）：审批自动排队 need_input，任务挂起等用户裁决；
- 用户点"停止"= 取消挂起审批并中止。

## 3. 服务器特有边界（不能照搬本机模型的点）
1. **路径体系**：工作区=/srv/rw-workspace；平台=/srv/harness-workbench；密钥在 .env/root/.rw-keys.env——read/write 会话的 limitPath 必须覆盖这两类敏感根（已实现：限工作区）。
2. **数据库**：db_query=global（SELECT 可查全部库，含平台库）→ 只读会话也保留（审计需要），db_write 仅在 full/guard（guard 需审批）。
3. **服务重启**：只读/写会话不可 reload_platform（MUTATING 已有）；full/guard 走 reload_platform 协议（回复后重启），禁止手动 systemctl（中断自身）。
4. **进程面**：run_command/run_long_task/kill_process 仅 full/guard（guard 审批）；后台 job 属平台管理对象（非用户会话私有）。
5. **多渠道**：wechat/feishu 会话默认 read（权限最小化），需要提升走 guard 审批卡（渠道内确认）。
6. **工具启用集（5.3c）独立于权限层**：permission=能不能执行该能力；启用集=要不要提供该工具；两层叠加（full 但未启用工具→指引去勾选；启用但权限不足→权限拒绝）。
