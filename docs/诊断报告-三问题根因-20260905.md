# RW 三问题诊断报告（假开始/高消耗/中断）· 2026-09-05

> 状态：只诊断未改码。数据源：conv184 消息取证 + 近 3 天 usage_stats/agent_runs/tool_calls + hooks.js/checkpoint.js 代码审查。

## 问题 1：假开始（最核心，牵动另两问题）
**现象**：短指令（"继续验证/落地/按ABCD落地"）→ assistant 数秒内回复"开始执行——先确认…"，**0 工具调用即结束**；用户质问→道歉再承诺→又假开始，单日循环 3-4 次（conv184 #649-#668）。
**根因（铁证）**：RW 对话有"双路径"判定——`needsTools()` 用关键词正则决定是否走带工具路径。**假开始的每条 user 短指令都不含工具关键词（"继续验证""落地""按ABCD落地"→ TOOL意图❌）→ 走了"普通对话路径（无工具）"→ 模型只能口头承诺"开始执行"却无工具可调=假开始**。命中关键词的指令（"自检代码…彻查"）都正常执行（13 次工具调用）。模型与平台曾多轮"彻查假开始"（141 轮/¥28）却归因于 B6b/commit/记忆错乱——**从未查到路由漏判这一真根因**。
另：普通路径存在空答（#676 assistant 内容为空）。
**方案**：
1. 移除 needsTools 预判，对话统一带工具（工具 schema 增量 ~2-3k tokens/轮，普通问答模型自然不调用；根治漏判）——结构性改动，需确认。
2. 普通路径空答兜底（同 agent 路径）。
3. 准则 5.5 已立（承诺-动手），修复 1 后自动自愈。

## 问题 2：消耗高（简单任务 10+ 元）
**数据**：近 2 天 deepseek 2656 轮 ≈¥250（估算）；每轮输入 **avg 46.6k / max 137.9k**；最贵任务 run94（conv184 彻查假开始）**141 轮 ¥28**，top5 合计 ¥94。
**根因**：
1. 假开始→用户反复催→模型在**错误方向长跑**（141 轮彻查一个它找不到的 bug）= 最大单项浪费；
2. 每轮输入 4.6 万（语义折叠阈值过晚：>110 条消息/45k 字符才折叠，60-140 轮任务大半不触发）；
3. 门禁/失败后重试放大：3 天 156 次工具失败（命令纪律 26/SELECT 23/ENOENT 14…），失败后模型多轮换路硬试；
4. 中断后 resume 全历史重放。
**方案**：折叠阈值下调（消息 110→60、字符 45k→25k、间隔 30→15 轮）；连续失败轮计数（连续 N 轮含失败工具→挂起问用户）；GLM 慢响应适配（超时放宽/重试一次）；GLM 单价校准。

## 问题 3：中断
**数据**：近 3 天 interrupted 8 次：用户点击停止 4 / **服务重启中断 2** / 缺 full 权限 1 / aborted 1。
**根因**：
1. 自升级 reload 撞用户任务（RW 当天多次 reload：模型列表修复/占位符检疫等均重启，运行中任务全断）；
2. 慢模型 90s 硬超时（chatOnceWithTools AbortSignal 90s）——GLM/长思考轮可能超时即"执行出错"中断；
3. 用户手动停止 4 次=假开始/无响应导致的放弃（前因见问题 1）；
4. SSE 长连接偶发断（驱动侧亦多次遇 terminated）——待独立排查（负载/内存/网络）。
**方案**：reload_platform 前检测同账号 running 会话（有则提示/延迟）；超时按模型放宽（120-180s 或 retry）；假开始根治后减少人为停止。

## 附带发现（RW 自写代码缺陷，代码审查）
1. hooks.js danger_command_guard 读 `args.command`（run_command 实参为 `cmd`）→ **破坏性命令守卫实际失效**（与其复验时自述一致）；
2. system_write_guard 挂 before '*' 且只查 args.path → **读类工具读 /etc 也会被"写入拦截"误拦**（语义 bug，近 3 天未大规模触发）；
3. hooks_list/undo_checkpoint 未注册进 TOOL_META/启用集/豁免 → 与工具启用集冲突（undo 可能不可用）。
