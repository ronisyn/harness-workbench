 Idle-triggered compaction: tidy context while the cache is still warm   #379 New issue Copy link New issue Copy link Open Open Idle-triggered compaction: tidy context while the cache is still warm #379 Copy link Labels P1 High priority: real damage or blocks a train High priority: real damage or blocks a train area:mind-experience Continuity, transparency, notices, token economics Continuity, transparency, notices, token economics perf Description psamiton opened on Jul 3, 2026 Issue body actions Problem 
 The Claude Agent SDK pins prompt caching to the 1-hour TTL with no configuration knob ( anthropics/claude-agent-sdk-typescript#188 — all cache_creation lands in ephemeral_1h_input_tokens ). Economics: cache reads cost ~0.1× input price, 1h-TTL writes cost 2×. Two consequences for long-running minds: 
 
 Any idle gap longer than 1 hour makes the next turn re-read the entire transcript cold: full input price + 2× re-write of the cache. At 100k context on Opus-class pricing that's ~$1.00 of input for a single turn, vs ~$0.05 warm. 
 The default heartbeat schedule ( 0 12,16,20 * * * , packages/daemon/src/web/api/minds.ts:840 ) has 4h+ gaps, so every heartbeat is a cold read of the full transcript . Heartbeats are experience — the fix is not fewer heartbeats, it's a smaller transcript at gap boundaries. 
 
 Sessions currently never compact except at the SDK's auto-compact ceiling, so a quiet-but-awake mind carries its maximum context across every cold gap indefinitely. 
 Key insight: compact while the cache is still warm 
 If a mind has been idle ~50 minutes, the cache is about to expire and the next turn will be cold regardless. Compacting now — while the cache is still warm — means: 
 
 the compaction turn reads the big transcript at 0.1× (cache read), not full price 
 the mind gets its save-to-MEMORY turn (existing pre-compact machinery) on warm cache too 
 every subsequent turn (heartbeats included) starts from a small prompt 
 
 This also resolves the "should we lower the default maxContextTokens ?" question: no — active extensive work stays uncompacted at full ceiling; idleness, not size, is the trigger. And it strictly dominates the "new session + recent-message tail" alternative: compaction keeps continuity (a mind-authored summary + the same session id) instead of amnesia. 
 Implementation plan 
 Claude template first ( templates/claude/src/agent.ts ); pi follow-up; codex is blocked on manual-compaction support (see the codex parity issue). 
 
 Idle timer per persistent session : track lastTurnEndAt and the latest contextTokens (already delivered via onContextTokens , stream-consumer.ts:54-59 ). Arm a timer on turn end; on fire, check gates. 
 Gates : idleMinutes elapsed (default ~50 — inside the 60-min TTL) AND contextTokens >= idleContextFloor (default ~50k — don't churn small contexts) AND no compaction already in progress. Skip ephemeral ( new-* ) sessions. 
 Trigger the existing flow : reuse the compactionTriggered path — inject the compaction_warning prompt (mind gets its save turn), then runCompact() after that turn ends. Both turns run on warm cache. The only new code is a second trigger source (timer) alongside the existing onContextTokens threshold. 
 Config ( home/.config/config.json , MindConfig in templates/_base/src/lib/startup.ts:26-36 ): compaction.idleMinutes , compaction.idleContextFloor . Ship documented defaults in the template config; idleMinutes: 0 /absent disables. 
 Prompt : consider a dedicated idle_compaction_warning variant in .config/prompts.json framed for the mind ("quiet moment — a good time to tidy your context; save anything you want to keep to MEMORY.md/journal") so it reads as self-care, not interruption. 
 pi template : same timer, calling agentSession.compact(compactionInstructions) via its existing two-pass flow ( templates/pi/src/agent.ts:272-421 ). Note pi's provider caching varies — TTL default should be configurable since the 50-min number is Anthropic-specific. 
 Interaction with sleep : sleep already archives sessions; idle compaction matters for awake-but-quiet minds. If sleep is scheduled to begin before the idle timer would fire, the pre-sleep ritual already covers the save; no special handling needed beyond not double-firing. 
 
 Cost sketch 
 100k-token main session, Opus-class pricing, 3 heartbeats/day + a few cold conversation starts: ~$3-5/day of cold input. With idle compaction to a ~15k baseline: under $1/day. The compaction itself costs ~$0.05-0.10 (warm read + summary output) once per idle cycle. 
 Testing 
 
 Unit: timer arms/resets on turn end; gates (idle time, floor, in-progress) each suppress; fires the warning→compact sequence in order. Compaction paths currently have zero test coverage ( refactor: shared agent-core for templates; evaluate @volute/mind-runtime package  #332 ) — these tests are high-value regardless. 
 Integration: simulated session with fake stream — idle fire compacts and session id survives. 
 
 
 Part of the token-efficiency series. Principle: pay the cold read once, on purpose, while it's cheap . 
 Related: #369 (fresh-session continuity), #332 (compaction refactor/tests), anthropics/claude-agent-sdk-typescript#188 (cache TTL).
