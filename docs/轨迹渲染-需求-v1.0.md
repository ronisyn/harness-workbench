# RW 轨迹渲染 · 需求开发文档 v1.0

> 版本：v1.0（2026-09-02）｜状态：待开发｜来源：3080 轨迹形态转化（用户需求）
> 目标：880 智能体对话中，把 Agent 的"执行轨迹"（工具调用全过程）以 3080 同级的体验渲染出来

## 一、背景与目标

用户在 880 与 AI 对话时，AI 会调用工具执行任务（读文件/写代码/查库/搜索等）。
当前轨迹**只在"设置→轨迹"Tab 里事后查看**（tool_calls 表），**对话中不可见**——用户看不到 AI "正在做什么、做过什么"。

**目标**：让执行过程像 3080 一样**在对话流中实时、可见、可回看**。

## 二、轨迹的定义（什么算一条轨迹）

一条轨迹 = 一次工具调用，含：
| 要素 | 说明 | 数据源 |
|---|---|---|
| 序号 | 本次任务中的第几次调用 | 前端递增 |
| 工具名 | read_file / write_file / run_command / db_query… | tool_calls.tool_name |
| 参数 | 调用参数（路径/命令/SQL） | tool_calls.args |
| 结果摘要 | 返回内容/错误 | tool_calls.result_summary |
| 耗时 | 毫秒 | tool_calls.duration_ms |
| 状态 | done（成功）/ fail（失败）/ running（运行中） | tool_calls.status |
| 时间 | 调用时刻 | tool_calls.created_at |
| 归属 | 属于哪条 assistant 消息/哪轮 | conversation_id + message_id |

## 三、渲染形态（对话流中）

### 3.1 触发点
- AI 的工具路径（function calling）执行时，**轨迹实时出现在正在生成的 assistant 消息上方/内部**
- SSE 已有 `tool` 事件（{name, result}），前端需扩展为完整轨迹对象

### 3.2 卡片形态（对齐 3080 工具调用展示）
```
┌─ 🔧 run_command ──────────── 1.2s ✓ ─┐
│ ls -la /srv/harness-workbench         │  ← 参数（等宽字体）
├──────────────────────────────────────┤
│ drwxr-xr-x server web src package.json│  ← 结果摘要（默认折叠截断）
└──────────────────────────────────────┘
```
- **默认状态**：展示工具名 + 状态徽标（✓ 成功 / ✕ 失败 / ● 运行中动画）+ 耗时
- **可展开/收起**：点击展开完整参数与结果（参数、结果各一行摘要，默认折叠截断 1-2 行）
- **失败高亮**：fail 状态红边/红色徽标，结果摘要显示错误信息
- **运行中**：工具执行期间显示加载动画（…/转圈），完成刷新为 ✓/✕

### 3.3 位置与布局
- 轨迹卡片出现在 **assistant 消息之前**（AI 先调用工具，再基于结果回答）
- 同一次任务的连续工具调用按顺序纵向排列，卡片间紧凑（间距 4px）
- 回答文本在轨迹序列之后（消息气泡内：轨迹区 + 回答区）

### 3.4 消息流结构（数据）
```
assistant 消息渲染 = 轨迹区（N 张卡片） + 回答区（Markdown）
```

## 四、实时流式（SSE 扩展）

当前 `/api/chat` SSE 事件：
- `tool`（工具事件：{name, result}）→ 升级为完整轨迹：`{type:'tool', tool:{name, args, result, status, duration_ms, seq}}`
- 前端收到 → 追加卡片到当前 assistant 消息的轨迹区

## 五、持久化与回看（已具备）

- tool_calls 表已记录全部轨迹（名称/参数/结果/耗时/状态/时间）✅
- "设置→轨迹" Tab 已有事后查看 ✅
- **增强**：轨迹 Tab 与对话消息**关联展示**（打开某条 assistant 消息 → 显示其执行的全部轨迹）

## 六、交互清单

| 交互 | 说明 |
|---|---|
| 展开/收起卡片 | 点击切换完整参数/结果 |
| 复制参数/结果 | 卡片右上角复制按钮 |
| 失败定位 | 红色徽标 + 错误摘要首行 |
| 运行中反馈 | 卡片加载动画 + "运行中"状态 |
| 停止生成 | 既有"■ 停止"按钮中断，运行中卡片标"已中断" |
| 回看历史 | 历史消息的轨迹从 tool_calls 加载渲染（打开旧会话时） |

## 八、技术实现要点（开发指引）

1. **后端**（server/index.js）：
   - SSE `tool` 事件补充 args/status/duration_ms/seq 字段
   - 提供按 message_id 查轨迹 API：`GET /api/messages/:id/toolcalls`
2. **前端**（src/Chat.jsx + api.js + styles.css）：
   - `streamChat` 的 onTool 回调收集轨迹对象
   - assistant 消息渲染为 {轨迹卡片列表} + {Markdown 回答}
   - ToolCard 组件（展开/收起/状态/耗时/复制）
   - 打开历史会话时按 message 加载轨迹
3. **样式**：太阳大地色卡片（背景 #fffdf8、边框 #e6d5b0、成功绿/失败红徽标、等宽字体参数）
