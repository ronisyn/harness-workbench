# 模型接入与厂商自注册（v1 · 2026-09-17）

> **本文是"客户网关 / 内网推理怎么接进来"的唯一操作与契约出处**（v0.3 §4.3「可切云端/客户网关/内网推理」）。
> 代码侧唯一实现＝`server/llm/providers.js` 的"自注册厂商"节 + `server/index.js` 的三个写口；
> 验收夹具＝`test/provider-register.test.mjs`（7 条，含反向核对）。
> 关联：`docs/MCP接入指南.md`（外部工具/连接器接入口）、`server/llm/gateway.js`（唯一出网发送点）。

## 一、两类厂商，各有一个权威（不许打架）

| 类别 | 谁说了算 | 启动时怎么同步 | 能不能改 |
|---|---|---|---|
| **内置厂商**（deepseek/glm/ark/…，10 家） | **代码清单** `server/llm/providers.js` 的 `PROVIDERS` | 按 id **逐家补齐缺行**（含默认模型）；**已有行一个字都不改**（人工的 `enabled`/名称不被启动覆盖） | 只能改代码清单（它随代码进 VCS） |
| **自注册厂商**（客户网关 / 内网推理） | **`providers` 表** | `provider_key` **不在代码清单里**的行，启动时载入内存注册表并参与路由 | 只能走本文的 API（代码清单里没有它们） |

**判据只有一条：`provider_key` 在不在代码清单里。** 于是两边各管各的 id 空间：
- API **拒绝**占用内置厂商的 id（`id 与内置厂商冲突`），也**拒绝**删除内置厂商（`内置厂商的 id 由代码清单占用，API 不许删除`）；
- 启动同步**不会**把自注册厂商挤掉（它只按 id 补内置厂商的缺行），也不会把内置厂商的行当成"部署方注册的"重新载入。

> 为什么改了这一处（2026-09-17）：原来是"**表里一行都没有**才整批播种内置厂商"。那样一来，客户先在库里
> 注册了自己的网关，内置厂商的行就永远补不上了（两处会打架，且症状是"菜单里少了几家"这种查不出来的事）。
> 现在按 id 逐家判：缺哪家补哪家，已有的不碰。

## 二、注册一个客户网关/内网推理

### 请求体字段（＝既有清单同形字段）

```json
{
  "id": "acme_gw",
  "name": "客户网关",
  "base": "http://10.0.0.5:8000/v1",
  "keyEnv": "acme_gw",
  "defaultModel": "acme-1",
  "capabilities": ["chat", "tool"],
  "chatModels": ["acme-1", "acme-2"],
  "timeoutMs": 180000,
  "capabilitiesDeclared": { "vision": false }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 2–32 位小写字母/数字/`_`/`-`，以字母开头；**不许**与内置厂商 id 冲突。它进日志、进 `provider` 字段、进 URL 路径 |
| `name` | ✅ | 显示名（≤64 字，照 `providers.name` 列宽） |
| `base` | ✅ | **OpenAI 兼容** base URL，`http(s)://` 绝对地址、不带查询串/片段（≤255 字）。末尾斜杠会被去掉——既有拼接口径是 `base + '/chat/completions'`。内网地址直接写 `http://10.x.x.x:端口/v1` |
| `keyEnv` | ✅ | **`config.keys` 的槽位名**（小写标识符）。见下一节"凭证" |
| `defaultModel` | ❌ | 显式指定厂商时 model 缺省就用它（`settings.default_models` 的覆盖仍然优先） |
| `capabilities` | ❌ | 能力**标签**（菜单维度），缺省 `["chat"]`。它不是排他性的能力全集，语义见 `server/modelcaps.js` |
| `chatModels` | ❌ | 主对话模型清单，入库供菜单可选（走既有 `syncChatModels`） |
| `timeoutMs` | ❌ | 该厂商单轮超时（毫秒，正数）；不写＝沿用网关既有缺省 |
| `capabilitiesDeclared` | ❌ | 三维**显式否定**（`vision`/`tool`/`reasoning` 布尔），判定与后果见 `server/modelcaps.js` |

**未知字段一律拒绝**（`未知字段 apiKey（清单同形字段只有 …）`）：拼错的字段静默忽略最坑人
——尤其 `apiKey`/`apiKeyEnv` 这类"看起来像密钥"的名字，在这里**没有**对应的凭证路径。

### 凭证：只走既有那一条路

1. 注册时**只写引用名**（`keyEnv`），**不收明文密钥**：密钥不进请求体、不进 `providers` 表、不进任何响应（§9）。
2. 槽位按**既有命名约定**解析环境变量：`keyEnv` 大写 + `_API_KEY`
   （`acme_gw` → `ACME_GW_API_KEY`，与 10 个内置槽位里 9 个的写法逐字一致）。
   把密钥写进部署机的 `.env` 或环境变量即可；`config.keys[keyEnv]` 是**唯一读取点**
   （`llm/gateway.js` 的 `resolve`、`/api/models`、auto 路由回落、`autotitle`、渠道轮次都读它）。
3. 取值为空 ⇒ 该厂商显示"未配置 Key"，显式选中它会如实报 `厂商「X」未配置 API Key`（不静默降级到别的厂商）。

### API

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/providers` | 列表（鉴权同上）。本次**只增**一个字段 `source: "manifest" \| "registered"` |
| `POST` | `/api/providers` | **注册**。已是注册厂商 ⇒ `400 厂商已注册：…（改它用 PUT）`；占用内置 id / 字段非法 ⇒ `400` + `message`（+ `problems` 数组逐条） |
| `PUT` | `/api/providers/:id` | **更新**（`id` 以路径为准，body 里若带 `id` 必须一致）。**是整体替换**：清单同形字段需一并给出（只改一处也带上 `id/name/base/keyEnv`），不做隐藏的字段合并——只传一半、另一半悄悄沿用旧值＝两处说法。未注册的 id ⇒ `400 未注册的厂商：…` |
| `DELETE` | `/api/providers/:id` | **注销**。只对自注册厂商生效；内置 id / 未注册 id ⇒ `400`。同时清掉该厂商的 `models` 目录行 |

- 鉴权：三个写口都用既有的 `requireAuth`（**没有新增权限面**，与其它管理端点同一把锁）。
- 审计：`provider:register` / `provider:update` / `provider:delete` 各落一条 `audit_log`。
- 成功响应：`{ ok:true, provider:{…规范化后的条目…}, models:<入库目录条数>, catalogError, keyHint }`。
  `keyHint` 直接告诉你密钥该写哪个环境变量名（只给名字，不给值）。
- **失败不留半态**：先校验、再落库、**最后**注册进内存（内存注册表是路由的唯一判据）⇒
  库写失败时不会出现"本机能路由、重启后不能"的幽灵厂商。
- **UI 本轮未做**（如实登记）：只提供 API；控制台里看不到注册表单，也没有"我的网关"列表页。

### 启动行为（与清单同步不打架）

1. 内置厂商：按 id **补齐缺行**（含默认模型），已有行不动。
2. 自注册厂商：`provider_key` 不在清单里的行 → 校验 → 载入内存注册表；
   - 校验不过的行**报错并跳过**（`[providers] 自注册厂商载入失败（该行被跳过，不影响内置厂商）：…`），不阻断启动、也不静默；
   - **默认模型从既有 `models` 行补回**：`providers` 表没有 `defaultModel` 列，它就是 `models` 里行名为
     `<厂商名> 默认模型` 的那一条（与内置厂商播种时的口径逐字一致）；查不到就留空串（**不猜**"第一个模型就是默认"）。
     `PUT` 改名时那一行的行名会**同步改掉**（否则改一次名，重启后默认模型就丢了）。
3. 之后既有那一步 `syncChatModels` 会把各厂商目录核一遍（自注册厂商同样走它）。

## 三、边界与不做的事（如实登记）

- **不做 UI**：控制台里的厂商列表/表单不在本批（`/api/providers` 只增 `source` 字段，前端未消费）。
- **不改价目**：`llm/gateway.js` 的 `PRICE` 没有自注册厂商条目 ⇒ 成本按既有缺省价估算
  （`calcCost` 的兜底档）。要精确计费得另立项（那是对客/结算面的事）。
- **删除不抹历史**：注销只删配置（`providers`/`models` 行），对话与账本里存的是 provider 字符串，不会被改写。
- **不同步 `settings.default_models`**：那个键是运营的覆盖层，注册不自动写它（谁设谁负责）。
- **不碰 `RW_KEYS`/credentials 文件**：厂商密钥只走 `config.keys` 这条既有路径，与连接器的凭据库是两回事。
