# 对外产品与服务（官网的信息源）

> **本文是什么**：把"我们到底卖什么"讲成一套**完整、有效、一致、成体系**的表达。
> 本文**不是**官网文案，是官网的**信息源**——官网每个页面都从本文取内容，不自己发明。
>
> **本文的规矩**：只写**对外可承诺**的，不写内部分层。凡是"我们内部怎么实现"的内容，一律不在本文出现
> （那是 `45` / `31` 的事）。客户看到的每一句，都要能对应到一份可执行的设计。

---

## 0. 一句话

> **我们不卖 AI 工具。我们给你配数字员工——在你自己的系统里干活，用你的账号，产出交给人复核。**

三个必须先说清的边界（对外最容易含糊、也最容易被客户误解的地方）：

| 边界 | 对外表述 | 为什么必须先说 |
|---|---|---|
| **不是聊天机器人** | 它产出**可复核的交付物**（计划表、单据草稿、代码），不是一个对话框 | 不说清，客户会拿"它能不能陪聊"来评估我们 |
| **不碰你的生产数据** | 它**永不直写**你的业务系统；写操作一律**填草稿 + 人点提交** | 这是客户最大的顾虑，也是我们最大的差异化 |
| **不卖 token** | **月订阅（按席位）**，不按消耗转卖。模型 Key 可自持，也可我们代持并**按实际用量平价对账** | 不先说，客户会以为又是"按 token 计费的 AI" |

## 1. 产品体系（三层语言，所有对外材料统一用这三层）

| 层 | 是什么 | 对外怎么讲 |
|---|---|---|
| **荣易数联平台** | **管** | 管人、管权限、管钱、管边界。客户不需要理解它 |
| **agent** | **干** | 可插拔的"手和脑"。客户不需要选它，我们按岗位配 |
| **岗位包** | **业务配置** | 一个工种的能力、边界、交付物。**这是客户唯一需要理解的概念** |

> **对外只讲第三层。** 前两层是我们的实现，讲多了客户会开始问"你用的是哪个大模型"——那是个不该在售前展开的问题。

---

## 2. 能力域（对外的 8 个，不是内部的 27 项）

内部有 27 项能力，但官网**不能列 27 条**。归拢成 8 个域，每个域配一句"这解决你什么"：

| # | 能力域 | 解决什么（客户语言） |
|---|---|---|
| 1 | **身份与组织** | 你的员工用飞书登录，不用记新密码。**权限不从组织架构继承**——防止有人在飞书里改个部门就拿到更大权限 |
| 2 | **数据边界** | 同一份数据，**不同的人、不同的员工，看到的行和列都不一样**。成本价可以给"团队结算价"而不是"采购价"，而且**参数同时遮蔽**，断掉反推 |
| 3 | **运行隔离** | 每个员工、每个项目一个独立运行环境。**它到不了它不该到的地方**——不是靠"它不会去"，是靠"它去不了" |
| 4 | **写路径与审批** | 不可逆的动作（下单、付款、发消息）**必须人点**。支持双人复核、先出预演方案、按成熟度逐步放开 |
| 5 | **模型接入与路由** | 多厂商多模型，可路由、可降级、可指定。**缓存按客户硬隔离**——跨客户永不命中 |
| 6 | **外部系统接入** | **没有 API 也能接**（四档：现代 API / 有数据出口 / 只有界面 / 明确拒绝）。所有外部通信走连接器 |
| 7 | **交付与流转** | 交付物有验收标准、有版本、有送达记录。产出直接进你的飞书/邮件，不只在界面里 |
| 8 | **知识与经验** | 它干过的活会沉淀成经验。**但"必须遵守"不算知识**——规则和知识分开管，规则改动要人批 |

## 3. 岗位库（对外最有说服力的部分）

**不写"我们能做很多岗位"，而是列具体岗位 + 它产出什么 + 谁复核。**

| 岗位 | 产出 | 交给谁 | 状态 |
|---|---|---|---|
| **备货计划专员** | 备货计划表（附"为什么这么算"） | 采购专员 → 复核人 | 一期 |
| **软件工程师** | 代码 + 自测报告 | 技术团队 | 一期 |
| 采购专员 | 采购单草稿 | 复核后提交 | 规划 |
| 库存对账专员 | 差异清单 | 技术团队 | 规划 |
| 数据面运维 | 数据面巡检报告 | 技术团队 | 规划 |
| 售前客服 | 接待记录 + 线索卡 | 客户成功 | 规划 |
| 售后客服 | 工单 + 归因结论 | 客户成功 | 规划 |

> **对外只放到"岗位名 + 产出 + 交给谁"这一层**，不放到"能力配置"级别——那是签约后的事。
> 这样客户能判断"能不能用"，又不会拿着我们的配置去比价。

## 4. 装载形态（判据：数据能不能出内网）

| 形态 | 适合谁 | 数据在哪 | 我们要什么 |
|---|---|---|---|
| **云端**（默认） | 数据可出内网 | 我们托管，**每客户独立实例** | 外网可达 + 一个只读/可写的专用账号 |
| **数据面** | 数据不能出内网 | 数据面装在**你的内网**，控制面在外 | 一台内网机器 + 出网通道 |
| **桥接** | 只有界面、没有接口的旧系统 | 你侧一个轻量桥接件 | 一台能开浏览器的机器 |

**两条明说的边界**（不写清会在实施时扯皮）：
- **我们不用 SSH 进你的服务器。** 所有操作走平台通道，可审计、可撤销
- **完全离线不支持。** 需要外网（哪怕只是出网通道）

## 5. 计费

- **月订阅（按席位）**——任务分**轻 / 标准 / 重**三档，判据客观（子代理数 / 轮数 / 数据量），不按"感觉"算
- **模型 Key 两种方式**：
  - **你自持**（推荐）——账单直接走你的云账号
  - **我们代持**——按**实际用量平价对账**，不加价
- **首客锁 12 个月价**，之后每季度复核

## 6. 客户数据承诺（对外信任状，九条）

| # | 承诺 |
|---|---|
| 1 | **数据归属是你的**，我们只是受托处理 |
| 2 | **不用于训练**——不可撤销地不用你的数据训练任何模型 |
| 3 | **不出境**——训练与推理都在境内 |
| 4 | **加密与访问控制**——传输与存储加密，最小权限 |
| 5 | **我们不查看你的内容**——运维通道与业务通道分离，运维过程全程留痕 |
| 6 | **留存 15 天含备份自动清除** |
| 7 | **可导出、可删除**，退出时返还 |
| 8 | **退出返还**——合同终止后按约定返还并可彻底删除 |
| 9 | **不主动向执法披露**——除依法必须，且会通知你（法律禁止通知的除外） |

## 7. 官网信息架构（7 个一级）

> **组织原则：场景优先，不做功能罗列。** 完整功能清单推到文档站，首页只放场景。
> 这条抄的是百炼与 WorkBuddy **共同**指向的做法（决策 181）。

```
首页
产品与服务     8 个能力域（§2）
岗位库         按职能筛（§3）
接入与安全     三形态（§4）+ 九条承诺（§6）
价格           席位 + 模型用量（§5）
试用与上手     ⭐ 公开试用沙盒 + 四步上手
开发者         对外 API 目录（受控公开）
关于与联系     含售前客服 agent 入口
```

### 7.1 首页结构（按顺序）

| 区块 | 内容 | 为什么放这 |
|---|---|---|
| **1 一句话 + 副标题** | §0 那句话 | 3 秒内说清"卖什么" |
| **2 岗位卡（3 张）** | 备货计划专员 / 软件工程师 / 售前客服 | **岗位切入**，客户立刻知道能买什么 |
| **3 "为什么不自己招人"** | 四条对比 | ⭐ **必答题**：岗位切入一定会被问这个，主动答比被问强 |
| **4 沙盒入口** | "现在就试一个备货计划专员" | 转化主力 |
| **5 数据承诺** | 九条里挑最硬的 4 条 | 打消最大顾虑 |
| **6 接入形态** | 三形态缩略 + 链接 | 让技术团队看到可行性 |
| **7 价格摘要** | 一句话 + 链接 | 不放具体数字在首页（留资） |

### 7.2 场景卡的固定四字段模板

**每张卡都必须是这四个字段，顺序不变**（决策 181，这是内容生产的 SOP，避免每页重新发明结构）：

| 字段 | 写法 | 例子 |
|---|---|---|
| `·推荐用户` | **写痛点，不写部门** | ✅"被月度备货计划困住的供应链主管" ❌"供应链部门" |
| `·能力描述` | 一句，动词开头 | "按销量与在途库存算出建议备货量，并说明理由" |
| `·典型任务` | 两三条具体的活 | "4 月上半月备货计划" |
| `·产出与交付` | 产出什么、交给谁复核 | "备货计划表（含计算依据）→ 采购复核" |

> ⭐ **`·推荐用户` 写痛点不写部门**——这是 WorkBuddy 的写法，值得抄。
> 写部门等于"这跟我没关系"；写痛点等于"说的就是我"。

### 7.3 "为什么不自己招人"这一块怎么写（不回避）

| | 招一个人 | 配一个数字员工 |
|---|---|---|
| **上手时间** | 1–3 个月熟悉业务 | **装载后即可上岗**（含上岗自检） |
| **产能波动** | 会请假、会离职、会疲劳 | 稳定；忙时加席位 |
| **出错** | 出错不一定留痕 | **每一步可查**：查了什么数据、用了什么规则 |
| **权限** | 人能看到的东西很难精细限制 | **行、列、聚合三层精细控制** |
| **换人** | 经验跟着人走 | **经验留在平台**（账本 + 资产），人换了活不断 |

**同时要诚实说清不适用的情况**（不写会在成交后变成纠纷）：
- 需要**面对面关系**的岗位（谈判、客情维护）
- 需要**承担法律责任**的决策（签字、用印）
- 数据**完全不能出任何通道**的场景

### 7.4 公开试用沙盒（决策：放）

| 项 | 设计 |
|---|---|
| **是什么** | 一个**共享的演示工作区**，用**合成的演示数据集**，不属于任何客户 |
| **能干什么** | 触发演示员工（备货计划专员）· **复核它的产出、改数额、看它为什么这么算** · 看完整运行过程 |
| **不能干什么** | 传自己的数据 · 改岗位包 · 配连接器 · 导出 |
| **产出** | 一律带"演示数据"水印 |
| **为什么这样切** | 最有说服力的体验不是"看它答得聪明"，而是**"它算完了，我改了 3 个数，它告诉我为什么原来那么算"**——这正好展示我们跟聊天机器人最本质的区别 |
| **技术上要注意** | 访客**不做认证、只判权限**（`10` §3）。但访客会产生会话与运行记录，所以**会话归属、审计、计费都要能容纳"非注册访客"这个主体**——这条属于"后加要动已有数据"，**不能后补** |

### 7.5 定价页的能力对照表（行分组）

**行分组固定为四组**（决策 182）：

| 分组 | 内容 |
|---|---|
| **基础功能** | 岗位、席位、交付物、复核 |
| **高阶能力** | 多工作区、子代理协作、经验沉淀、自主触发 |
| **设置与安全** | 数据边界、审批策略、审计、装载与自检 |
| **企业特性** | 独立实例、数据面部署、专属支持、SLA |

> ⭐ **"设置与安全"独立成组**——把**治理**提升为与功能并列的一等展示轴。
> 客户里真正签字的是安全/合规那一环，他们要在价格页上就能看到"这条我关心"。

## 8. 验收标准

| # | 标准 |
|---|---|
| W1 | 官网每个页面都能追溯到本文某一节；**不允许官网上出现本文没有的承诺** |
| W2 | 首页 3 秒内能被回答"卖什么"；**不出现"AI 赋能""数智化"这类空词** |
| W3 | 每张场景卡都是固定的四字段模板，`·推荐用户` 必须写痛点不写部门 |
| W4 | 内部 27 项能力**不在官网出现**，只出现 8 个能力域 |
| W5 | 三个边界（非聊天机器人 / 不碰生产数据 / 不卖 token）在首页出现至少一次 |
| W6 | "为什么不自己招人"这一块必须同时写**适用**与**不适用**，不回避 |
| W7 | 九条数据承诺可逐条对应到 `46` 的条款 |
| W8 | 价格页不出现 token 单价（ADR-6）；模型用量表述为"平价对账" |
| W9 | 沙盒的"不能干什么"要写出来（不是只写能干什么） |
| W10 | 每个岗位在官网上都写明"产出什么 + 交给谁复核" |
