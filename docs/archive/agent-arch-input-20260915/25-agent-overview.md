## 1. agent 是什么（定位与边界）

| 层 | 是什么 |
|---|---|
| **平台（Ronisyn）** | 管：多租户、账本、审计、交付、治理、模型网关、岗位包、**任务编排调度**、对外接口 |
| **agent** | 干：**引擎**（思考循环）+ **运行时**（工具 / 上下文组装 / 记忆 / 沙箱接口 / 子代理机制） |
| **岗位包** | 配：身份、提示词、技能、知识、工具授权、交付物、任务编排模板、触发、运行环境、模型策略、交互形态 |

**判据**：**"管"的归平台，"干"的归 agent。**

**两条容易搞混的边界（已定死）**：
- **上下文**：**组装机制归 agent，准入规则归平台**（准入是安全决策，不能交给可被劫持的一方）
- **沙箱**：**接口在 agent，实现在平台**（换 agent 不用重做沙箱，换沙箱也不用改 agent）

**权威文档**：[`19`](./19-platform-vs-agent-boundary.md)（边界）· [`15`](./15-harness-reuse-assessment.md)（harness 评估）· [`17`](./17-rw-status-and-architecture-revision.md)（roni 现状）

## 7. 循环检测（新增，借鉴 harness 实查）

### 7.1 harness 的真实做法（实读源码）

| 项 | harness 实际 |
|---|---|
| **默认阈值** | `[3, 5, 8]` —— 连续相同调用到 3 / 5 / 8 次分别触发 |
| **性质** | **"分级提醒"，不是"熔断"**——原话："enriches post-execute decisions... **without vetoing or rewriting calls**" |
| **第 3 次** | 温和提醒："你在用完全相同的参数重复同一个调用。仔细分析之前的结果；如果任务没完成，换方法或换参数。" |
| **第 5 / 8 次** | 详细提醒：点名工具、连续次数、参数 |
| **参数比较** | **深度 key 排序后再比**（否则 `{a:1,b:2}` 和 `{b:2,a:1}` 会被当成不同参数） |
| 参数预览 | 截断到 **500 字符** |
| 来源标记 | 标为"插件"，**防止被渲染成用户提示** |

### 7.2 我们怎么落地（我拍）

**照搬 `[3, 5, 8]` 分级提醒 + 不熔断。**

**理由**：熔断会**误杀合法的重复调用**（比如轮询任务、等外部系统就绪）。提醒让模型自己判断。

**和已有预算机制配合**：如果提示到 8 次仍不收敛，**由预算软着陆兜底**（`08` §6：70% 收敛提示 → 85% 换便宜模型 → 100% 优雅中止）——**不需要在循环检测里再叠一层熔断**。

**验收标准**：同一工具 + 相同参数连续调用第 3 次 → 上下文里出现温和提醒；第 5 次 → 详细提醒；**全过程调用不被阻止**。
