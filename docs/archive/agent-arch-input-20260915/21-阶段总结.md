## 0. 一句话定位

**Ronisyn 是一个"把 agent 装配成业务岗位、安全托管、多租户运行"的平台；roni 是平台里自研的那个 agent。**

一句话商业模式：**不卖 token，卖"能入驻、能算账、能验收的业务岗位"。**

## 1. 三层结构（最终版）

| 层 | 是什么 | 谁 | 换不换 |
|---|---|---|---|
| **平台（Ronisyn）** | 管：多租户、账本、审计、交付、治理、模型网关、岗位包、**任务编排调度**、对外接口 | 自研 | 只有一个 |
| **agent** | 干：引擎（思考）+ 运行时（工具/上下文/记忆/沙箱/**子代理机制**）。可插拔零件 | **roni（自研）+ DS harness（开源）+ codex harness（开源）** | 可插拔，一期 3 个（Claude 不用） |
| **岗位包** | 业务配置：身份、提示词、技能、知识、工具授权、交付物模板、**任务编排模板**、触发方式 | 配置 | 一个岗位一个 |

## 3. 岗位包 = 九块

身份 · 能力 · 权限 · 交付物 · **任务编排** · 触发 · 运行环境 · 模型策略 · 交互形态

**第 5 块"任务编排"是本会话后期新增**（你的备货例子逼出来的）：声明"这个岗位的活，拆成哪几个子代理、并行还是串行、怎么汇总"。

## 4. 关键共识（业务/战略，最容易丢）

1. **护城河不在 token、不在引擎，在壳（= 平台 + 业务封装）**：懂客户业务、19 个连接器、十几个岗位包、学习闭环。
2. **计划在 Excel、执行在 ERP** → agent 天然停在 ERP 门口（写路径之外）。
3. **人改 agent 产出的每一次，都是它变准的燃料**（学习闭环是一等公民）。
4. **混合部署现在就要做**：客户数据中台在客户服务器上，数据面装进客户内网、数据不搬家。
5. **能精确查的，别让模型记**：对照表/库存/订单走连接器查询，不进上下文、不进向量库。
6. **能确定的规则要固化，别让模型现场悟**：任务编排模板、业务参数都是这个原则的落地。
7. **信任是靠不出错挣来的，不是靠权限设计给的**：岗位逐段交付，稳定后再"一步做到底"。

---

## 5. 合规约束（硬性，见 `02`）

- 不卖 token、不做 API 聚合中转、不向客户交付厂商凭证
- 客户自持 Key 为主；客户没 Key 时服务商代持、**平价对账不赚差价**（但"平价"是商业加分项、**非条款豁免**，代持仍建议走官方伙伴授权）
- 境外模型（GPT/Claude/Gemini）一刀切排除
- 预充值三红线：余额不可提现/转让/跨商户；专户管理；不承诺利息返利
- "金额小可豁免"是误区，法律没有这条

## 6. harness 调研结论（见 `15`/`16`）

- harness（dsh）**MIT 开源**，版本 0.1.0-rc.7
- 它的架构与我们独立设计**逐条收敛**（SandboxProvider 契约、fail-closed 审批、spill 大结果落盘、token-meter 驱动压缩……）
- **harness = 零件库**，不是平台替代品——它缺多租户/账本/审计/交付（这些正是 Ronisyn 要自研的）
- 服务器化成立（web host + headless + schedule + 会话持久化到 SQLite），但多租户隔离要自研
- Codex Harness 也 **MIT**（已查证）；Claude Code 闭源
