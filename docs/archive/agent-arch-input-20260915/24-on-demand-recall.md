## 0. 先纠正我自己

**harness 里根本没有向量检索**（包列表里没有 vector / embed / rag 相关包）。它的"按需召回"是另一套四件组合：

| harness 的做法 | 对应包 |

| **比例制压缩 + 中段修剪** | `dsh-compaction-basic` + `tool-result-pruner` |

## 1. 真正的根因：不是"没有向量"，是"预先注入太多"

你 RW 总结里的诊断是"**没有按需召回（无向量检索、无分层记忆调度），所以省不到根上**"。

**但"无向量检索"不是根因。** 真正的根因是——**roni 把大量东西"预先塞"进每一轮的上下文**：

| roni 现在每轮都注入 | 量级 |
|---|---|
| 技能全文 | 单技能上限 **1.6 万字符** |
| 知识 | **12 条**（自动注入） |
| 项目说明 | **1.6 万字符** |
| 系统提示（身份/环境/纪律） | 几百行 |
| 运行时快照 + 最后 8 条 git 提交 | 每轮都变 |

**这些是"预注入"，不是"按需召回"。** 轮次越多、注入越多，成本线性叠加。

**harness 的原则正好相反：能"按需取"的，绝不"预先塞"。**

---

## 2. 四件事（把"预注入"改成"按需取"）

### 2.1 技能：从"全文注入" → "按需加载工具"（照搬 harness）

**现在**：技能全文进系统提示，本会话跨轮生效 → 每轮都带着 N × 1.6 万字符。

**改成**：
- 系统提示里只放**技能目录**：每个技能一行（名字 + "什么时候用它"）
- 模型需要时，调用"**加载技能**"工具，取回该技能全文
- **这就是 harness 的 `dsh-tool-skill` 模式**

**结果**：上下文里只带"技能清单"（几十行），不带全文。一个 10 个技能的岗位，一轮省下十几万字符。

### 2.2 知识：从"每轮注入 12 条" → "按需检索"

**现在**：每轮自动注入最近 12 条知识（前 5 条还带 300 字摘要）。

**改成**：给 agent 一个"**查知识**"工具，需要时才查。

**检索方式我拍：先全文（FTS5），向量作为可选增强**（理由见 §3）。

**结果**：不需要知识的轮次（占大多数），一条都不带。

### 2.3 结构化数据：连接器精确查询（强化既有原则）

**这是最大的一块，也是最容易被忽略的。**

历史备货表、库存记录、订单明细——**这些不是"检索"，是"精确查询"**。它们应该：
- 结构化导入（你之前问的"Excel 历史存档怎么放"——就是这个）
- agent 通过连接器按"SKU / 时间 / 平台"**精确查**
- **不进上下文、不进向量库**

**结果**：需要某个月某个 SKU 的历史备货量，一次精确查询就拿到；而不是靠"检索"猜出来。

### 2.4 会话历史：比例制压缩 + 中段修剪

已在 `23` 定死：压缩按**模型窗口的 80%** 触发、保留 16%；历史工具结果按 **8192/4096/1024** 修剪。

## 3. 全文 vs 向量：我的判断

**我拍：先做全文检索（FTS5）打底，向量作为"留位置、后补"的增强。**

**理由三条：**
1. **harness 就没用向量**——它用 FTS5，说明对 agent 场景够了
2. **向量要额外成本**——embedding 模型调用 + 向量库维护，是持续开销
3. **中文业务术语全文够用**——"备货计划""库龄""头程时效"这类词，全文匹配很准

**什么时候才真需要向量：** 当"**语义相似但用词不同**"成为刚需时。比如用户问"库存积压情况"，而资料里写的是"库龄过高"——全文匹配不到，向量能匹配到。

**这是"接口留位置"的事**（不是现在做，也不是糊弄）：检索接口设计成"可换检索后端"，将来插向量库不用重构。

---

## 4. 结果与验收

**做完后的总结果**：

| 原来（每轮注入） | 改成 | 省下 |
|---|---|---|
| 技能全文（N × 1.6 万字符） | 只放技能目录，按需加载 | 大 |
| 知识 12 条 | 按需检索 | 中 |
| 项目说明 1.6 万字符 | 按需（只在相关任务时注入） | 中 |
| 结构化历史数据靠"记" | 连接器精确查 | 大（且更准） |

**验收标准（三条，可测）**：
1. 一个不用知识的轮次，上下文里**一条知识都没有**（对比现在固定 12 条）
2. 一个不用技能的轮次，上下文里**只有技能清单，没有技能全文**
3. 查一个历史 SKU 的备货量，走**精确查询**，不进上下文
