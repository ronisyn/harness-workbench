# 29 · 经验管理与防腐

> 状态：方案，技术决策由我拍。平台侧第 3 步（新增议题）。
> 前置：`28`（交付物流程——经验的来源）· `24`（按需召回——经验的消费）· `26`（治理层——经验的归属）
> 由来：调研阿里 QoderWake 时发现我们缺两块——它叫"**五维自进化**"和"**防腐机制（Anti-Rot Governance）**"。

---

## 0. 一句话

**我们的学习闭环"只进不出"——人改了就记下来，从不清理。半年后 agent 脑子里全是过时经验，越用越乱。**

**这份文档补两件事：经验怎么**分类**进来（五维），以及怎么**不腐烂**（防腐）。**

---

## 1. 五维经验模型（借 QoderWake）

> ⚠️ **先消歧（Day 3 补）**：这五维里的**"记忆"**指的是**内容类型**——"这条内容属于'发生了什么'"。
> 它和 [`architecture`](./architecture.md) §5.3 / [`03`](./03-role-package.md) §1.1 的**"记忆分层"**（工作/会话/工作区/数字员工）**不是一回事**：
>
> | | 回答的问题 | 性质 |
> |---|---|---|
> | **记忆分层** | 存在哪、活多久 | **存储**概念 |
> | **"记忆"维** | 这条内容是什么类型 | **内容分类**概念 |
>
> **另有一条三级流水（Day 3 定）**：**原始记录 → 记忆 → 经验**。
> 原始记录（会话/运行日志）是原料；**记忆** = 提炼后的事实（"3/15 改过 320→400"）；**经验** = 从记忆里得出的可复用判断（"美东安全库存要 35 天"）。
> **知识 ≠ 经验**：人给的进知识库（[`33`](./33-knowledge-layer.md)），agent 攒的进这里。

**每次执行后，经验沉淀到五个维度**——这样 agent 才能"带着这套东西"去干活：

| 维度 | 存什么 | 备货场景的例子 |
|---|---|---|
| **记忆** | 这次**发生了什么** | "3/15，备货专员把 SKU-123 的备货量从 320 改成 400" |
| **技能** | **怎么做**一件事 | "备货分析要先查近 30 天销量，再查在途" |
| **策略** | **什么情况下怎么做** | "美西仓安全库存取 30 天，美东取 35 天" |
| **验证规则** | **怎么算做对了** | "备货量不能突破库龄 180 天的滞销线" |
| **工作流** | **多步骤怎么串** | "备货 = 销量子代理 + 库存子代理 + 物流子代理 → 汇总" |

**这五维我们其实都有**（记忆在 `03`、技能在 `12`、工作流在 `22`、验证在 `28`、策略在 `26`）——**缺的是"把经验自动路由到这五维"的机制**。

> ⚠️ **"这五维我们都有"不等于"经验库是第五个存储块"**（Day 3 修正）。
> 五维是**归类方式**，不是**存储位置**：归类后的经验，**技能维归技能库、工作流维归岗位包、验证规则维归策略、策略维归策略/经验库、只有"记忆"和"策略"维真正落在经验库**。
> 所以 [`33`](./33-knowledge-layer.md) §1 把它列成"知识层的第 ③ 块"是**简化说法**，权威关系以本节为准。

## 2. 经验从哪来（四个来源，强度递减）

| 来源 | 强度 | 说明 |
|---|---|---|
| **① 人的修改** | ⭐⭐⭐⭐⭐ | 人改了 agent 产出 + **填了原因**（`28` 已定要记）——**最强的信号** |
| **② 验收失败** | ⭐⭐⭐⭐ | 交付物被验收否了 → 反推是哪条经验错了 |
| **③ agent 复盘** | ⭐⭐⭐ | 任务结束后自己总结（roni 已有"主动复盘"，这里接进来） |
| **④ 人主动教** | ⭐⭐⭐ | 客户技术团队直接写一条策略/技能 |

**①最强**——因为它带着"人为什么这么改"的解释，那是模型自己永远推不出来的。

## 3. ⭐ 经验怎么归类（三段式，不全自动）

**问题**：人把备货量从 320 改成 400，这条经验该进哪一维？

| 如果原因是 | 应该进 |
|---|---|
| "这个 SKU 在美西仓，安全库存要按 35 天算" | **策略** |
| "下个月有大促，要提前备" | **记忆**（这次）+ 可能形成**策略** |
| "流程漏了查在途" | **工作流** |

**我拍：三段式——人填原因 → agent 提议归类 → 人确认。**

```
① 人复核时填改动原因（`28` 已定要记）
        ↓
② agent 提议："这条建议归到【策略】，因为它是'某条件下怎么做'"
        ↓
③ 人确认 / 改成别的维度 → 入经验库
```

**为什么不全自动**：模型猜错维度 → **污染经验库**，比不沉淀更糟。
**为什么不全人工**：太重，人不会坚持做。

**结果**：归类准确、人有掌控、且人只需要"点个头"。

## 4. ⭐ 防腐机制（Anti-Rot Governance）

**这是"越用越准"的另一半。**

### 4.1 三类腐坏，三种处理

| 腐坏 | 表现（备货场景） | 处理 |
|---|---|---|
| **过时** | 策略写着"旺季提前 30 天备货"，但旺季定义变了 | **淘汰**（标记过期，不再被 agent 用） |
| **冲突** | 一条说"这家供应商交期 7 天"，另一条说"14 天" | **裁决**（保留更新的/更权威的，旧的作废） |
| **失效** | "双 11 促销规则"已经结束 | **撤回**（标记失效） |

### 4.2 怎么发现腐坏（三个触发，不靠人盯）

| 触发 | 机制 |
|---|---|
| **时间触发** | 每条经验带**有效期**，到期自动提示复核 |
| **冲突触发** | 新经验入库时与旧经验冲突 → **入库时就提示裁决** |
| **失败触发** | agent 用了某条经验、结果被验收否了 → **该经验自动标记"可疑"** |

> ⭐ **"验收否了"有两种来源，都要接上**（Day 3 补）：
> ① **人复核否定**（`28` §3）；
> ② **机器自动验证否定**——生效写（`06` L3）执行后，系统自动比对"目标系统的实际状态 vs 预期效果"，不符即失败（`06` §2.3.6）。
> **②是 agent 学习"生产环境真实行为"的唯一途径**，尤其在没有测试环境的连接器上——它同时是**首跑护栏**和**经验来源**。

### 4.3 谁来裁决（我拍：不自动裁决）

**客户技术团队 / 业务负责人**人来定。

**理由**：裁决涉及**业务判断**（"交期到底是 7 天还是 14 天"只有业务知道）。系统负责**发现和提示**，不负责**替人做业务决定**。

**结果**：经验库不会腐烂，但业务决定权始终在人手里。

---

### 4.4 容量与保留（Day 3 补：防"只进不出"的第二道闸）

上面治的是"**内容腐烂**"，这里治"**量无限涨**"。两个问题不同，都要堵。

| 项 | 我拍 |
|---|---|
| **默认保留** | 经验**默认不设硬性上限**，但**带有效期**（§4.2 时间触发） |
| **压舱处置** | 到容量阈值时按"**用得多的留下，没人用的下架**"排序——依据是 **① 使用频次 ② 可信度（被验收否定过的降级） ③ 多久没被召回** |
| **下架 ≠ 删除** | 下架 = 移出**按需召回的候选集**（防腐 §4.3 的"淘汰/撤回"就是这个动作）；**内容仍在，可查、可恢复** |
| **删除** | 只有两类真删：① **从未被召回且已过期**（系统自动清理，留一条计数）② 人显式要求 |
| **归属** | 经验挂 `客户 → 工作区 → 数字员工`（`26` §1.2）。**数字员工归档时，经验跟着进归档态，不自动消失** |
| **客户退出** | 随 `01` §6.4 的密码学销毁一起删（销毁租户 KMS key → 不可恢复） |

> **为什么"下架 ≠ 删除"是必须的**：经验是**客户资产**。客户会问"你们凭什么删我的东西"。系统只应该**降低它的权重**，删除权**在人手里**。
>
> **和"数字员工退出"的接口**：员工退出时经验资产怎么处置（留 / 转 / 销），**✅ 已在 [`36`](./36-digital-employee-lifecycle.md) §7.1 定死**——
> **留在原归属**（业务事实留工作区、岗位经验转归档只读），**只有被显式标记为"资产带毒"的异常退出才销毁**（`36` §7.1 ③）。
> 本文只保证一条底线：**经验不因员工退出而凭空消失。**

## 5. 和现有设计的咬合（一张图）

```
经验的来源          →  `28` 交付物流程（人的修改 + 原因）+ 验收 + 复盘
       ↓
经验的归类          →  **本文 §3**（三段式：人填 → agent 提议 → 人确认）
       ↓
经验的存储          →  **五维**（记忆 / 技能 / 策略 / 验证规则 / 工作流）
                        ⚠️ 五维是**归类去向**，不是五个存储块：
                           技能维 → 技能库（`12`）｜工作流维 → 岗位包（`03`/`22`）
                           验证规则维 → 策略（`26`）｜记忆/策略维 → 经验库
       ↓
经验的治理          →  **本文 §4**（防腐：淘汰 / 裁决 / 撤回）
       ↓
经验的消费          →  `24` 按需召回（agent 干活时按需取，不预先塞）
                        ⚠️ 取之前先过数据视窗（`34`）
       ↓
经验的归属          →  `26` 治理层（挂到 客户 → 工作区 → 数字员工）
```

## 6. 验收标准

| # | 标准 |
|---|---|
| E1 | 人改了 agent 产出并填了原因后，能形成一条经验，且**归到五维中的某一维** |
| E2 | agent 能**提议**归类维度，人**能改**，改完才算入库 |
| E3 | 经验带**有效期**，到期会被提示复核，且**不再被 agent 使用** |
| E4 | 新经验与旧经验冲突时，**入库时就提示裁决**，不是等到出错 |
| E5 | agent 用了某条经验导致验收失败，**该经验自动被标记"可疑"** |
| E6 | 被淘汰/撤回的经验**不出现在 agent 的按需召回里**（真正失效，不只是标记） |

---

## 7. 为什么这一条是产品差异点（不是内部机制）

**它是"越用越值钱"和"越用越乱"的分水岭。**

- **没有防腐**：agent 学得越多越乱，客户会觉得"这东西越用越不准"
- **有防腐**：经验被持续清理，**agent 随时间变准**——这是能写进营销、客户能感知的东西

QoderWake 把它当核心卖点（"复利式成长、越用越准"），我们也应该当卖点，**而不是藏在内部机制里**。
