# 合规约束清单（架构用）

> 来源：`compliance-report-llm-api-resale.md` + 两份并行调研（厂商服务条款 / 境内监管）
> 定位：**不是法律意见书**。这是把调研结论翻译成"架构必须怎么做"的约束清单。
> 建议：真动手前，就"我这个具体形态要不要办证"这一条，去属地通信管理局做一次窗口咨询，并让律师看一眼。

---

## 0. 一句话结论

**决定风险的不是规模大小，是这一个开关：你卖的是"token"，还是"软件"。**

- 客户账单上是「消耗 350 万 token × 1.15 元/百万」→ **你在卖 token** → 合同违约 + 电信许可 + AI 备案 + 资金监管，四条线一起命中
- 客户账单上是「本月 86 次备货分析、142 次详情页优化，服务费 XXX」→ **你在卖软件** → 基本不沾

两路独立调研（厂商条款 / 境内监管）撞到同一个答案。这条线可以当结论用。

## 1. 最现实的风险不是罚款，是断供

上游协议已明文禁止转售，**一放量就会被封，比监管来得快**：

| 厂商 | 条款 | 后果 |
|---|---|---|
| 阿里云百炼 | 服务协议 4.6：「未经我们及相关权利人书面许可，**您不得转售本服务及平台内模型**」 | 封号、剩余额度回收 |
| 智谱 | GLM Coding Plan 团队套餐协议 6.2：「不得以**转售、代售、转包装、聚合转发**等方式向任何第三方提供」 | 封号 + **违规期间消耗金额 5 倍违约金**，已充值不退 |
| 智谱（开放平台） | 服务协议 7(7)：禁止「分销、转售…**二次封装、服务中转、聚合中转**」 | 同上 |
| MiniMax | 用户协议 4.5(c)：禁止「**独立于任何集成的应用程序**分许可、转售或分发」 | 封号 |
| Kimi | 开放平台协议：「**不可转让、不可再许可**，仅供内部使用或向最终用户提供服务」 | 需授权 |
| DeepSeek | 用户协议 3.6(4)：禁止未经授权「转让、出租、出售或提供分许可、转许可」 | 需授权 |
| 百度千帆 | 《专项约定》2.13：「您**无权**针对本服务进行二次分发，包括但不限于转让、许可、授权第三方使用」；2.6.4(10)：禁止「非法转售或对外提供本服务，或以商业化目的使用本服务」 | 限制功能 → 暂停/终止 → 封号 |
| 火山方舟 | 《专用条款》3.1：「如您就本服务进行商业使用或以其他方式直接或间接获得收益，则您**需要事先获得火山引擎的书面许可**」 | 立即终止许可 |
| 火山（豆包协议） | 2.1：不得「复制、转让、出租、出借、出售或提供分许可、转许可」 | 可要求**订单总额 10% 违约金**（可累计） |
| WorkBuddy（腾讯） | 企业版 8.4(4)：禁止「未经许可转售、分许可、出租、出借或向客户组织外第三方商业化提供本服务」；个人版 6.1(1)：禁止「将本服务用于**对外提供商业化 AI 能力**」 | 封号且**不退费** |

> ⚠️ **WorkBuddy 不是"大模型厂商的 API 额度"供应方。** 它是腾讯的订阅制产品（席位 + 积分，支持 BYOK），签约主体是腾讯云计算（北京）有限责任公司。把它和其他模型厂商并列会导致分类错误——它约束的是"订阅与积分"的流转，不是"API 额度转售"。**采购清单里应把它单独归类。**

**但四家都留了同一个口子**（措辞几乎一致）：

- DeepSeek 开放平台协议 1.1：「可以将模型能力集成于各种下游系统、应用或功能……向内部/外部的终端用户提供服务」✅
- 智谱：「集成至您自有产品、应用或功能中，并向终端用户提供服务的，**不视为前述受限行为**」✅
- MiniMax：只禁止「**独立于任何集成的应用程序**」的转售 ✅
- Kimi：「仅供内部使用或**向最终用户提供服务**」✅

→ **合规的定性靠"这是不是一个集成了模型能力的产品"来成立。**

## 2. 对架构的硬约束（这是本清单的重点）

### C1 · 计费单位不能是 token

- ❌ 客户界面出现「token 单价」「token 余额」「token 充值」
- ✅ 计费单位 = agent 干的活（任务数 / 单据数 / 岗位席位 / 分析次数）
- ✅ 消耗明细可以给，但给的是"干了什么"，不是"买了多少 token"

### C2 · 不向客户交付任何厂商凭证

不交付、不展示、不允许客户自带厂商 API Key 接入你的平台。凭证只存在于平台内部。

### C3 · 不做 API 聚合中转

不提供"一个 key 调所有模型"的对外接口。模型路由是**平台内部能力**，不是**对外产品**。

### C4 · 客户余额的三条红线（守住就不用先办支付牌照）

《非银行支付机构监督管理条例》第十五条明文排除"单用途预付卡业务"，所以 B2B 预充值一般不构成支付业务。但：

1. 余额**仅用于购买你的服务**——不可提现、不可转让给第三方、不可跨不相关商户通用
2. 预收款**专户管理**，不与自有资金混同，不用于投资/放贷
3. **不承诺任何利息、返利、投资回报**

> ⚠️ **"金额小可以豁免"是认知误区，法律没有这条一般豁免。** 金额小只影响执法关注度与罚则档次，不构成法律抗辩。

### C5 · 模型只走境内已备案的

**境外模型（GPT / Claude / Gemini）这条线一刀切排除。** 刑事风险最高处：暂行办法第二十条 + 网信办"境外模型无落地通道" + 信管函〔2017〕32号禁止未经批准跨境经营 + 已有"AI中转站"站长涉嫌非法经营罪被刑拘的公开案例（核心触发点是「账号池 + 逆向绕鉴权 + 跨境反代」）。

### C6 · 为"随时要备案"留好门（不要假设永久豁免）

豁免条件 = "未向境内公众提供"（暂行办法第二条第三款）。当前形态（少数特定企业客户、内部岗位使用、不开放注册）**大概率符合**，但：

- 官方**从未**对"B2B 转售算不算面向公众"给过口径 → 是"大概率"，不是"确定"
- **豁免很脆**：一旦对外开放注册 / 公开售卖标准版，豁免当天失效

所以架构要预留：
- 界面里**有位置**公示所用模型名称与备案号（一旦要登记就要显示）
- 模型配置能**一键切到已备案模型**
- 数据留存策略支持「**不留存使用者输入信息**」（暂行办法第十一条）
- 客户协议里预留内容安全责任条款（第九条）、投诉举报机制（第十五条）

### C7 · 上游授权链要能"倒推"

曼昆的**四个闭合**——授权链 / 业务范围 / 数据责任 / 账单证据。自检问题：

> **我卖出去的每一次调用，能不能倒推出它来自哪个上游、哪份授权、哪张账单？**

架构含义：每一次模型调用都要记录「上游厂商 + 授权依据 + 账期」，这是审计链的一部分，不是运维日志。

### C8 · 宣传纪律

- 未取得**书面**授权，不写"官方直连""官方授权"（上游已有多起严正声明否认代理）
- **不提厂商名字和 logo**——MiniMax 协议 6.8 禁止未经书面同意「对外披露我们是其服务提供商」
- 不承诺"无限量""绝对准确"

### C9 · 让客户清楚谁是实际服务提供方

汉坤指出：白标/转售须让客户清楚**实际服务提供方是谁**、以及**发票收款主体是否与服务主体一致**。这条与"贴自己 logo"并不冲突——logo 是你的，但**发票主体、服务责任主体**要写清楚。

## 3. 收费模式修订

| 原方案 | 判定 | 改成 |
|---|---|---|
| 定制项目收技术服务费 | ✅ 安全 | 不动 |
| SaaS 月费 + **token 溢价** | ⚠️ 月费安全，**token 溢价违约** | 月费保留；token 部分改成按 agent 干的活计价 |
| 轻应用**只收 token 溢价** | ❌ 最危险（纯 token 转售） | 加**最低月费**，token 只作内部成本 |

**收入结构建议**：主收入 = 订阅费 / 技术服务费（体现"壳"的价值）；token 只做透明的成本转嫁，小赚或不赚。

理由不只是合规——**纯加价转卖毛利薄、上游随时断供改价**，而你却要背许可、备案、数据、内容安全全套成本。汉坤、曼昆、界面新闻三篇判断一致：应向下游**增值层**迁移（权限管理、用量看板、审计日志、专属实例、行业应用封装、SLA 与支持）。

## 4. 三条路，选一条

**三家调研（厂商条款 / 境内监管 / 逐家条款）的共同结论：四家厂商全部不支持"默默加价转售额度"，但也全部承认"把模型能力封装进自己的产品/Agent，向最终用户收费"。**

| 路径 | 形态 | 合规成本 | 能赚什么 |
|---|---|---|---|
| **A · 客户自持 Key** | 让客户以**自己主体**去厂商注册、实名、下单、持有 API Key；你只做 agent 平台，调客户的 key | **零** | 技术服务费 / 订阅费 |
| **B · 上游官方伙伴** | 申请成为厂商**授权伙伴**，额度与计费走上游官方体系 | 需申请、需资质 | 官方分成（可含额度差价） |
| **C · 自己加价转售** | 自己采购、自己定价、客户向你充值换额度 | ❌ **合同违约 + 无证经营风险** | 差额，但随时断供 |

### 路径 A：客户自持 Key（零授权成本）

**这是最干净的一条，而且它彻底改变标的性质**——你卖的是"我帮你做的 agent 平台"，不是"模型额度"。前面 C1–C9 里关于 token 转售的约束**大部分自动消解**。

代价：赚不到 token 差价，只能收技术服务费。但注意，你原本的收费方案 1.1（技术服务费）和 1.2（SaaS 月费）**本来就是这个形态**——真正被拿掉的是 1.2 的 token 溢价和 1.3。

> 早期就建议过这条（客户自己开 key、成本天然归客户），现在从合规角度也指向同一个答案。

### 路径 B：上游官方伙伴（"客户充值"形态的唯一合规实现）

如果你确实想要"客户在我平台充值 + 看用量"，**只有走上游官方伙伴才成立**。按贴合度排序：

1. **火山引擎「代售伙伴」——最贴合，几乎一一对应**
   官方文档原文：「**代售模式指合作伙伴利用自身优势，将火山引擎公有云产品转售给最终客户**……**火山引擎只与伙伴开票和结算，客户与火山无票款关系**」
   「**代售类客户只能使用代售合作伙伴为其转入的虚拟额度进行下单、消费。代售合作伙伴可以为其关联的代售客户转入/转出虚拟额度。**」
   → 这和你设想的"客户预充值、平台里看用量"是同一个机制。还有「**违规伙伴公告**」专栏在清退不合规分销伙伴，说明这条通道是被管理、被认可的。
2. **百度智能云「代理转售类合作伙伴」** + 《渠道代付协议（代理）》原文：「客户将通过您购买百度智能云的产品和服务，需要您代为付款结算，**百度智能云向客户提供相应产品和服务**」
3. **阿里云「咨询和销售伙伴」**（云产品代理商/代销商，需企业实名 + 伙伴资质）；另有「云市场转售服务」（服务商授权 → 复刻商品上架 → 伙伴向用户开票、服务商向伙伴开票）
4. **智谱「大模型合作伙伴计划」**：招募要求明确写了「**代销能力**」，并配「合作伙伴协议与管理规范」
5. **Kimi**：企业合同 / 折扣通道（`platform.kimi.com/contact-sales`）
6. **DeepSeek / MiniMax**：未查到任何成文代理计划，只能走商务邮箱单独谈

### 路径 C：不建议

**境内未查到"自己定价、自己充值、自己交付 token"的规模化合规先例。** 且它同时触发：上游合同违约（先到）、电信业务无证经营、GenAI 备案缺失、资金监管。

### 一个值得注意的有利条款

**《百度千帆专项约定》2.7.6**（七个厂商里唯一把"Agent"写进条款的）：
> 「您将百度智能云 API 接口**封装至您的应用、Agent 或网站**的，应确保您应用或网站用户遵守本服务相关使用规范……」

配合 §10/§11「您可以向您的最终用户（如有）收取费用」「我们与非注册于本平台的您的最终用户**没有直接关系**」——**这是所有厂商里对"Agent 产品"最明确的承认**。

> ⚠️ 但百度协议内部有张力：§8.3 又说授权仅供「**个人和非商业使用**」。§2.7.6 与 §8.3 如何协调，**协议本身没写清楚**，这正是需要向百度商务书面确认的点——不要自己解读成"允许"。

## 5. 待确认清单（Go / No-Go 前置）

- [ ] **上游到底允不允许你转卖**——逐家拿**书面**授权，不是口头"我们是正规渠道"
- [ ] **你的交付形态是否构成经营电信业务**——向**属地通信管理局**窗口咨询。问两个具体问题：(a) 以自己名义销售、自己定价、承诺可用性、自己收费、客户在平台看用量并预充值，是否构成经营电信业务？(b) 若构成，申请 **B25 信息服务（经营性ICP）** 还是 **B11（含互联网资源协作服务）**？
  ⚠️ 本次调研**未查到任何官方文件**能回答这个问题，网上任何人拍胸脯说"不用办"或"必须办"都是推演。
- [ ] **能否走"登记"而非"备案"**——向属地网信办确认：调用已备案模型能力的"**应用或功能**"由地方网信办登记。但**纯 API 转售能否归入"应用或功能"，未查到官方口径**
- [ ] **主体条件**——经营性互联网信息服务（省内）注册资本一般需 **100 万元**（律师口径），并需人员、场地、技术方案、信息安全管理系统及配套评测
- [ ] **申办顺序**——拿上游授权 → 定业务形态 → 办许可/登记 → **最后才放量售卖**。清朗专项行动第一阶段首要整治的就是"应备未备"

- ❌ 未查到"API 转售应申请哪一增值电信子项"的官方认定
- ❌ 未查到"预充值金额小可豁免"的任何法规依据
- ❌ 未查到官方对"B2B 纯 API 转售是否属于面向境内公众"的明确口径
