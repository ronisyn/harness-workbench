## 2. 一条贯穿所有能力的判据

> **"管"的归平台，"干"的归 agent。**（`19`）

平台的一切能力都要能回答**归属**：`客户 → 工作区 → 数字员工 → 运行`（`26` §1.2）。

**审计、计费、经验、交付物全部挂在这条链上**——这是平台能力的公共坐标系。

## 3. 统一验收清单（平台侧）

### 3.1 治理层（`26`）

| # | 标准 |
|---|---|
| G1 | 任一消耗/事件/交付物，都能**倒推四层归属** |
| G2 | 权限能表达"**只读 + 需审批**"（两个正交维度） |
| G3 | 数字员工级策略**无法放宽**客户级策略（除非显式授权） |
| G4 | 审计事件里**没有原始业务数据**，但有"谁/何时/对什么/做了什么/结果" |
| G5 | 审计**不可篡改**（改任一事件，哈希链断裂可检测） |
| G6 | 删除租户后数据**密码学不可恢复** |
| G13 | **角色由客户自定义**，且**只能收紧不能放宽**数据视窗；同员工、不同人、**看到的数据不同** |
| G14 | **不存在"以平台运营方身份运行的 agent"**；运维通道与 agent 通道分离 |
| G15 | **人离职**能撤销授权、转交待审批项、处置在跑的运行 |

### 3.2 服务器资源治理（`27`）

| # | 标准 |
|---|---|
| S1 | 新项目部署**不需要知道其他项目**，也不会端口冲突 |
| S2 | 一个项目跑飞，**其他项目不受影响** |
| S3 | 对外只有 80/443，**归反向代理独占** |
| S4 | 新增项目时人能查到"还剩多少资源" |
| S5 | 一个项目升级依赖，**不影响其他项目** |

### 3.3 交付物流程（`28`）

> **送达的验收标准在 [`38`](./38-deliverable-delivery.md) §9（T1–T12）**——两个状态机分开，别混。

| # | 标准 |
|---|---|
| D1 | 人工修改后，**agent 原始版本仍可查** |
| D2 | 任一交付物能倒推四层归属 |
| D3 | 能从结构化数据**重新导出 Excel** 且一致 |
| D4 | 跨岗位交付是**同一对象**（不是副本） |
| D5 | "agent 原始值 vs 人改后值 + 原因"**完整记录** |
| D6 | "已确认"能**正确触发** `06` 的写流程 |
| D7 | 历史备货走**精确查询**，不走向量检索 |

### 3.4 经验管理（`29`）

| # | 标准 |
|---|---|
| E1 | 人的修改能形成经验，且**归到五维中的某一维** |
| E2 | agent **提议**归类、人**能改**，改完才算入库 |
| E3 | 经验带**有效期**，到期不再被使用 |
| E4 | 新经验与旧经验冲突时，**入库时就提示裁决** |
| E5 | 用了某条经验导致验收失败，**该经验自动标可疑** |
| E6 | 被淘汰/撤回的经验**不出现在按需召回里** |

### 3.5 模型网关与计费（`30`）

| # | 标准 |
|---|---|
| M1 | 所有 LLM 调用**都经网关**（绕过可查） |
| M2 | **agent 永远拿不到 Key** |
| M3 | 同一岗位两次调用的**可缓存前缀逐字节一致** |
| M4 | 模型故障自动退避重试，**且进程崩了重试不丢** |
| M5 | 一次调用能**归因四层** |
| M6 | 客户账单**只有"席位 + 任务数"，无 token 单价** |
| M7 | 任一客户**毛利低于阈值时告警** |
| M8 | 配额三层任一超限即停并上告警 |

### 3.6 沙箱（`05`）

| # | 标准 |
|---|---|
| X1 | 一个运行 = 一个沙箱 = **用完即毁** |
| X2 | 沙箱内**无长期凭证** |
| X3 | 别的客户/工作区不是"不许看"，是**"不存在"** |
| X4 | 沙箱内**不能提权** |
| X5 | **交付物是唯一出口** |

### 3.7 知识层（`33`）

| # | 标准 |
|---|---|
| K1 | 上传一份 SOP → 能检索到，且**带出处**（哪个文件哪一页） |
| K2 | 历史备货 Excel → 进**数据层**，**精确查询**，不进向量库 |
| K3 | 同一文件重复上传 → **不产生重复条目**（幂等） |
| K4 | 检索**先按归属过滤**，跨客户内容**从不进内存** |
| K5 | 源更新 → 重新摄入；源消失 → 标记可疑 |
| K6 | 知识带有效期，**到期不再参与检索** |
| K7 | 不用知识的轮次，上下文里**一条知识都没有** |
| K8 | 知识和经验**不混** |
| K9 | **扫描版 PDF** 能被检索到；解析失败**显式报错** |
| K10 | **对话内容不会自动入库**，只能提议、人确认 |
| K11 | 四层归属可见范围正确；数字员工**只看被授权的知识集** |
| K12 | 价格单改版后，**查历史用当时生效的版本** |
| K13 | 同工作区内，B 员工**检索不到** A 团队的知识 |
| K14 | **"必须遵守"的规则违反时会被拦**（不只是检索到） |
| K15 | 一份合同跨层落点时**共用文档身份**，可互相追溯 |
| K16 | 失效知识**移出检索候选但内容仍在** |

### 3.8 数据视窗（`34`）

| # | 标准 |
|---|---|
| V1 | 同工作区、同岗位包的两个数字员工，**互相查不到对方范围内的行** |
| V2 | 问"还有多少货"，得到的是**自己范围内的数**，不是全量 |
| V3 | 运营类员工看到的成本是**派生值**，**真实值不入上下文/日志/交付物** |
| V4 | 派生公式的参数**对同一视窗不可见**（反推不出来） |
| V5 | 跨范围聚合**默认不给**；给时**不可减法反推** |
| V6 | A 查过的数据**不会经记忆或缓存**被 B 拿到 |
| V7 | **未声明维度的数据源默认不可访问**（fail-closed） |
| V8 | 客户**新增维度/取值/改归属 → 平台零改动** |
| V9 | 岗位包里**不含客户特有的维度名与取值** |
| V10 | 子代理**拿不到比父级更宽的视窗** |
| V11 | 需要真实值的计算**下沉受信执行器**，agent 无真值 |
| V12 | 取数审计能回答"**以什么视窗查了什么**"，且不含业务数据 |

### 3.9 跨边界授权（`35`）

| # | 标准 |
|---|---|
| B1 | 无"可执行"档位时**做不到跨边界写**（能力上做不到） |
| B2 | **能发起**申请，且申请**不产生任何实际变更** |
| B3 | 审批方**由客户策略配置**——换角色，**平台零改动** |
| B4 | 审批通过后视窗**临时放宽并到期自动收回** |
| B5 | 归属转移**是事件**，不是静默 UPDATE |
| B6 | 转移后 A 的历史交付物**不被静默改写**，标记"依据已变更" |
| B7 | 转移后 A 的经验**不被 B 当成自己的** |
| B8 | 可见授权**只放宽视窗某维度**，不产生第二条读取路径 |
| B9 | 审批超时 = **自动拒绝** |
| B10 | 审计能完整回答**申请 → 审批 → 执行 → 结果**，不可篡改 |
| B11 | 跨两级以上边界**逐级审批** |
| B12 | 岗位包里**不含具体审批角色名/边界名** |

### 3.10 数字员工生命周期（`36`）
| # | 标准 |
|---|---|
| L1 | 五个状态可显式流转；**两条不可逆边需二次确认** |
| L2 | **未过上岗审核的草稿态员工：不派活、不给视窗、不发凭证** |
| L3 | **能力增删生成新契约版本**；任一时点能回答"它当时能干什么" |
| L4 | **收回权限立即生效；放宽必须有授权记录** |
| L5 | 停用期间**读数据也被拒绝** |
| L6 | 复职**回归原资产、不新建身份**，且**重过视窗检查** |
| L7 | 退出时**跑完当前运行**再停止接活 |
| L8 | 退出后**历史交付物不受影响**，且**归属链仍能指回该员工**（tombstone） |
| L9 | 退出后**对外 Key 立即吊销**；视窗与跨边界授权**全部失效** |
| L10 | 未完成任务**退回工作区任务池**；待确认项**转交或按超时拒绝关闭** |
| L11 | **退出 ≠ 销毁**：退出后身份记录仍在，销毁是独立动作 |
| L12 | **异常退出可标记"资产带毒" → 记忆与经验全部销毁、不转移** |
| L13 | 数字员工**不能让自己退出**；**AI 只能建议，人才能执行** |
| L14 | **"迁移到另一个工作区"不被支持**；换工作区只能重建，**记忆不随之迁移** |
| L15 | 就业账本**不可篡改、可回放**，含每次授权的批准人 |
| L16 | 客户**新增/调整一个数字员工的全过程，平台零改动** |
| L17 | **环境标记挂在连接器（能力）上且客户签字**；待确认按"生产 + 最严格"处理 |
| L18 | 有测试环境的走**双跑**、没有的走**生产只读探测**，三种模式可并存于同一员工 |
| L19 | 报告按【连接器 × 能力】聚合，**"不可测"（⊘）与"通过"视觉上完全不同** |
| L20 | 两次报告（预检/客户环境）**能自动对比**并列差异（含视窗指纹差异） |
| L21 | **"隔离待判"的资产真的停止召回** |
| L22 | 资产复核的**销毁不能批量**，且复核本身留痕 |
| L23 | 资产能**从任务/交付物反查**（三级下钻到原始会话/运行） |
| L24 | **`data_view.probe` 失败一律不许上岗**（唯一无例外项） |
| L25 | 非关键项跳过/不可测 → 可上岗，但**未验证能力台账在客户界面可见且客户确认** |
| L26 | 每个不可逆能力上岗时处于**预演态**；升级由**数据**决定，不由模型决定 |
| L27 | 自动验证失败 → **自动且立即降回预演态** |
| L28 | **批量上限永远存在**；超限走单独更高一级审批 |
| L29 | **L4 类操作不因成熟度降级** |
| L30 | 每次 L3 执行后**自动验证**，结果进账本与经验库；失败则相关经验标可疑 |
| L31 | 无测试环境时预演单**必须含"反向动作提案"**；真不可逆必须显式标记 |
| L32 | 网络隔离客户可用**离线自检工具**跑同一套检查项，产出同一结构报告 |

### 3.11 岗位包的编写与生成（`37`）

| # | 标准 |
|---|---|
| P1 | **一句话 → 生成九块齐全的角色草稿**，每块标注"AI 生成/待人确认" |
| P2 | 澄清**只问业务事实**，不问技术选择 |
| P3 | 质量门 **G1–G8 全过**才能固化；**G5 验收标准缺失则不许发布** |
| P4 | 生成的岗位包里**不含任何客户特有名词与取值** |
| P5 | AI **只生成模板层**；客户配置层（视窗取值/连接器/阈值）**一律留空待人填** |
| P6 | 安全相关默认值**一律最窄**（写权限 L0/L1、数据范围最小、批量上限 1） |
| P7 | 新建岗位时**先查库**，命中则提示"基于哪个已有岗位特化" |
| P8 | 三层模板可继承，且**模板内不含分支逻辑**（不是代码） |
| P9 | 岗位包**版本与契约版本独立**；升级是**提案**，客户可 diff / 拒绝 / **钉版** |
| P10 | 交付团队编辑界面**实时显示**"本岗位会拿到哪些能力/数据要求/写权限" |
| P11 | 岗位库里**高度相似的包提示合并**；长期无人用的提示归档 |
| P12 | **经验反哺模板必须脱敏 + 人确认** |
| P13 | **换客户、换数据源，只加连接器 + 配实例，不改岗位包**（ADR-4 量化验收） |
| P14 | **覆盖三档生效**：结构性内容（职责边界/schema/验收标准/权限声明）**客户改不了**；表述性与取值性可以 |
| P15 | **覆盖项记"基于哪个包版本"**；升级时冲突逐项让人选 |
| P16 | **发布过内部审批（业务+平台双人）+ 签名 + 血缘** |
| P17 | **交付物按产出时的验收标准快照判定**，不按最新版 |
| P18 | 灰度期**同一岗位两版并行**，用人工修改率/验收失败率/成本对比决定去留 |
| P19 | **回滚是"发一个回到旧行为的新版本"，不是撤销**；期间交付物**标记来源版本** |
| P20 | **硬下架只有平台方能做，且必须立即通知** |
| P21 | **一包多实例升级逐个原子生效**，账本可回答升级期间状态 |
| P22 | **派生包标注是否已分叉**；基底升级时未分叉自动合并、已分叉逐项评估 |

## 6. 平台的边界（哪些**不**属于平台）

**明确排除，避免越界设计**：

| 不归平台 | 归谁 |
|---|---|
| 引擎的思考循环 | agent |
| 工具的具体实现 | agent（平台只托管沙箱与权限） |
| 上下文的**组装机制** | agent（平台只管**准入规则**） |
| 每个 agent 的对话渲染 | agent |
| 认知循环、循环检测 | agent |

**一句话**：**平台管"圈"，agent 在圈里干活。**

> **Day 3 补充**：**"圈"本身也是客户可配置的**（维度类型/取值由客户定义，`34` §3.3）——平台提供的是"造圈的能力"，不是某一套固定的圈。
> 平台里**不出现任何具体岗位名、团队名、审批角色名**；出现了，就说明把客户的组织结构写进了代码。

### 6.1 ⭐ roni 的"11 板块控制台"在新架构里去哪了（Day 4 第 2 轮自审补）

`17` §1 记录 roni 的对话界面**已经是一个完整业务后台**（11 板块：模型广场 / 工具集 / 技能库 / 知识库 / 进化集 / Agent / 扩展中心 / 任务 / 审计 / 设置）。

**新架构分了 49 份文档讲能力，但没回答"这些能力在界面上长什么样、roni 现有板块怎么归位"。** 不归位的话，实现时会出现"文档说有一套，代码里是另一套"。

**归位表（以 `19` §2 的归属为判据）**：

| roni 现有板块 | 新架构归属 | 界面归属 | 说明 |
|---|---|---|---|
| 模型广场 | `30` | **平台侧**（运营方配）+ 客户只读 | 客户不该看到 token 单价（ADR-6） |
| 工具集 | `03` §1.4 工具分档 + `04` 连接器 | **客户技术团队** | 从"静态数组 + DB 行"改为"声明 + 装载"（`18` §3） |
| 技能库 | `12` | 客户技术团队 | 不变 |
| 知识库 | `33` | 客户技术团队 + 业务用户 | 补：分层归属（`33` §4.3） |
| 进化集 | `29` 经验 + `33` §6.1 资产复核 | **数字员工详情页 → 资产页签**（`36` §7.3） | ⭐ **从"独立板块"改为"挂在员工详情页下"**——因为经验是挂归属链的（`26` §1.2） |
| Agent | `36` 数字员工生命周期 | **数字员工列表 + 详情页**（五页签） | ⭐ **"Agent 管理"= `36` 的生命周期操作界面** |
| 扩展中心 | `32` 技能/插件/岗位库 | 客户技术团队 | 客户自助拔插 |
| 任务 | `22` 编排 + `13` 生命周期 | 客户业务用户 | 不变 |
| 审计 | `26` §3 | 客户技术团队 + 运营方 | 补：脱敏（`26` §3.2） |
| 设置 | `26` 策略 + `34` 数据视窗 | 分三层身份（`32` §4） | ⭐ 要按 ADR-7 的三层身份拆权限 |
| **（新增）岗位库** | `37` §6 | **交付团队侧**（不是客户界面） | 客户只"引用 + 实例化" |
| **（新增）数据视窗** | `34` | 客户技术团队 | 与"设置"分开：它是一条独立的配置线 |

**三条结论**：

1. **11 个板块基本都在，但有两处要变**：**"进化集"和"Agent"合并进"数字员工详情页"**（因为它们的对象都是"某个员工"，不是全局集合）
2. **要新增两块**：岗位库（交付团队侧）、数据视窗（客户侧）
3. **每个板块都要按 ADR-7 三层身份拆权限**——roni 现在是一套界面，新架构下**同一功能对不同身份的可见范围不同**
