# 3080(DSH) 机制对照与 RW(880) 服务器化适配方案

> 依据：3080 真实源码（`@deepseek-ai/dsh` 安装目录、136 行 `--dump-config` 合并导出、
> config/agent-presets 四预设、用户 `~/.dsh` 配置层）。RW = 自托管服务器 Agent（Express+MySQL）。
> 原则：功能与可调性对齐 3080；架构按服务器环境适配（无本地 CLI/profile，鉴权=Web 登录，
> 配置落 MySQL settings 表 / 技能目录 / 仓库预设文件，全部可远程管理）。

## 1. 环境差异 → 等价物映射（“启动层/CLI flag”的服务器化）

| 3080（本地） | RW（服务器） | 说明 |
|---|---|---|
| `dsh --profile <name>` | 登录 880 → 会话 | profile=部署实例；RW 是常驻服务 |
| `dsh web / headless` | /api 路由（/api/chat、/api/tasks…） | headless≈定时任务(F14)/渠道 |
| CLI flag（--port 等） | settings 表 + 环境变量（.env） | RW 可调键见 §4 |
| `$DSH_HOME`（~/.dsh） | 服务器固定目录（/srv/rw-workspace、/root/.rw-keys.env） | 密钥不落库/不入 git |
| profiles/plugin 安装（pnpm） | 仓库代码 + scp/git 发布 + reload_platform | “装插件”=加注册表行+重启 |
| cordis.patch.yml 分层 | 设置/预设文件（settings 表 + docs/预设 yml 权威副本） | 机器级覆盖=服务器运维直接改 settings |
| 用户凭据（credentials-local） | Web 登录 + /root/.rw-keys.env | 已按服务端模型实现 |

## 3. “长任务执行”反馈差异（用户实测第 1 点）

- 3080 的表现来自：agent-loop 单步调度(并行≤10)+每步即时 commit 事件+轨迹持久化回放+空答兜底+重复工具提醒。
- RW 已修复链：空答自动执行摘要（无内容反馈根因）→ agent_runs 断点现场+心跳+重启自检+“继续任务” →
  循环 soft 提示→paused 挂起。剩余差距：无“重复工具提醒”逐轮措辞（round 提醒）、无 step 级并行（RW 串行=更保守，可接受）。

## 4. 可调规则标准（RW settings 表键位总表，UI=设置→能力/高级参数）

| 键 | 默认 | 语义（对齐 3080） |
|---|---|---|
| time_budget_min | 120 | 单轮预算(0=不限)≈timeout 族 |
| round_cap | 2000 | 轮次上限(0=不限) |
| loop_guard | 6 | 连续无进展→soft 提示(一半值)→paused(全值)（对齐 repeat-tool-reminder 精神） |
| max_parallel_tools | 10(已实现) | agent-loop.maxParallelToolCalls：同一步工具调用有界并行、结果按模型顺序提交；0=串行；set_limits parallel 可调 |
| temperature | 1.0 | 采样温度 |
| systemPrompt | 空 | 用户指令层（≈agent-instructions 用户覆盖） |
| permission.defaultPreset | full | 权限预设默认（对齐 danger-full-access） |
| compaction 阈值 | 40 条历史 | 触发摘要（对齐 compaction-basic 语义） |
| 输出 max_tokens | 8000 | 对齐 llm maxTokens 可调 |
| result 修剪 | 本轮实现 head/tail | 对齐 tool-result-pruner(8192/4096/1024) |
| 技能目录 | RW_SKILLS | 服务器路径可配 |
