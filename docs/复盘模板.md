# 复盘模板 v1（撑竿跳方案 WS6.2 交付件）

> 用法：每任务结束 3 行快复盘；被复测打回=强制完整复盘并 kb_add（title 前缀"打回复盘:"，KPI3 依赖）。

## 3 行快复盘（每个任务收尾 30 秒）
- 有效：什么方法/工具/习惯让任务更顺？
- 无效：什么拖慢了、绕路了、打回了？
- 下次：一条可执行的改变（技能/知识/规则落点）。

## 完整复盘（打回/重大偏差时用）
1. 目标与验收（原话）：…
2. 实际执行：轮数 __ · 成本 ¥__（对照预估：__）
3. 差异与根因：预期 vs 实际；根因归类（理解偏差/探索不足/验证缺失/工具误用/环境变化/规则陈旧）
4. 打回原因（若被打回）：用户原话要点；哪条验收没过；证据（文件/行号/输出）
5. 避免条款：写成一条可执行的规则（"下次遇到 X 先做 Y"）
6. 沉淀去向：
   - 技能（skill_save，name=…）还是
   - 知识（kb_add，title="打回复盘:<一句话>"）还是
   - 规则/方案修订（回流 docs/平台开发全集清单-v1.md，唯一总纲）
7. 复验：修复后 self-audit 两段通过；提测证据。

## 沉淀示例
- kb_add: title="打回复盘:改代码前必须先跑现有测试" body="现象…原因…下次…" scope=conv/global
- skill_save: name=xxx（改进现技能或新增）
