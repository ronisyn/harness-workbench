## §1 agent 是什么

### 1.1 一句话

**agent = 引擎（会想，可换）+ 运行时（能干活，自研核心资产）。**

```
┌──────────────────────── agent ────────────────────────┐
│ 引擎（可换）  认知循环 · 单轮推理 · 内部折叠 · 工具调用请求生成 │
│ 运行时（自研）工具系统 · 上下文组装 · 记忆存取 · 沙箱接口        │
│              子代理机制 · 循环检测 · 预算执行 · 诚实性信号      │
└───────────────────────┬───────────────────────────────┘
                        │ 两条接口（§1.4）
         ┌──────────────▼──────────────┐
         │ 平台（不在本文范围）           │
         │ 权限裁决 · 沙箱实现 · 数据裁剪  │
         │ 模型网关 · 编排调度 · 审批      │
         │ 账本与审计 · 交付物 · 界面 · 岗位包│
         └──────────────────────────────┘
```
**判据：平台"管"，agent"干"；岗位包"配"。**（引用归档 `19` §1、`25` §1）

### 1.2 一期三个 agent 并行

**roni（自研）+ DS harness + Codex harness**（Claude Code 不作主线引擎：闭源，且合规上需排除境外模型链路——见归档 `50` §1.1、`02`:L78）。
三者**同台竞技**：同一套平台、同一套岗位包、同一套围栏与账本。**换引擎=重写一个适配器，不重写业务资产**（引用归档 `07` §4）。适配器契约见 RD-10。

### 1.3 三条不可让渡边界

| # | 边界 | 理由 |
|---|---|---|
| 1 | **工具调用必须被平台可见** | 引擎直连外部系统＝平台失去**策略下发**与**事件留痕**；围栏方案下审计粒度降为**命令/策略级**（见 RD-01）。"脱敏"目前无机制定义（见 OP-14） |
| 2 | **上下文的准入规则归平台** | "放什么进去"是安全决策，不是性能优化 |
| 3 | **结束与预算由平台裁决** | 引擎说"我还想继续"不算数；烧钱的开关必须在平台手里 |

### 1.4 四条容易搞混的边界（已定死）

> **上下文**：组装机制归 agent，**准入规则归平台**。
> **沙箱**：**实现与规格集合归平台，用哪一档由岗位包声明，agent 只使用其中一档**。
> **预算**：执行在 agent，**裁决归平台**。
> **编排**：跑一个子代理归 agent；**派几个、给多少、谁来汇总归平台**。

### 1.5 岗位包：只读 + 冻结 5 个消费字段（**P0-2 修订**）

岗位包定义的 **owner＝平台**（现行载体＝《总方案》§5 壳定义 Schema）；**权威定义文档尚未定版**。
本文只**冻结 agent 侧消费的 5 个字段**：**身份 · 能力（可用工具/技能/知识范围）· 权限 · 运行环境 · 模型策略**。
**未定版前，agent 侧不得新增依赖字段**；九块与壳字段的逐块映射随平台侧定版（见 OP-13）。

## §2 架构总览：骨架 + 七面 + 两横切

```
┌──────────────────────────────────────────────────────────────┐
│ 接入面  对内事件契约(SSE) · 对外 headless · REST+SSE · Webhook · MCP │
├──────────────────────────────────────────────────────────────┤
│ 编排面  主循环 · 完成度判断 · 子代理 · 编排接口 · 触发器接口        │
├──────────────────────────────────────────────────────────────┤
│ 上下文面 五层稳定度 · 前缀冻结 · 溢出 · 确定性投影 · 计量驱动折叠    │
├──────────────────────────────────────────────────────────────┤
│ 扩展面  工具注册表（唯一入口）· 装载与裁剪 · 审批声明 · 审计         │
│         ├ 自研工具   ├ 插件   ├ MCP   ├ 连接器   ├ 引擎原生工具(围栏)│
├──────────────────────────────────────────────────────────────┤
│ 能力面  模型网关(能力声明) · 执行后端(双平台) · 记忆 · 技能          │
├──────────────────────────────────────────────────────────────┤
│ 保障面  权限 · 沙箱 · 数据视窗出口 · 凭据 · 状态恢复 · 预算 · 循环   │
├──────────────────────────────────────────────────────────────┤
│ 运行面  环境无关 · 配置注入 · 存储抽象 · 版本与迁移                 │
└──────────────────────────────────────────────────────────────┘
骨架（贯穿七面）：服务注册与替换 · 契约与协议 · 声明式配置 · 不变式 · 确定性与可重放
横切 A：可观测与评测（事件/轨迹采集与上报；**落账在引擎、对账在平台**；金标回归；C1–C4 仪表）
横切 B：装载与版本
```
- **本图是七面的唯一权威**；《引擎改造计划》§3 为沿引，不另行维护。
- **依赖方向**：上依赖下；骨架贯穿全部；同面不互相调用语义。**骨架不是第八个面**，是七面共同的承重结构。
- **骨架的实现口径**（P2 降级，防过度设计）：**服务注册＝显式工厂 + 接口 + 单一注册点**，不做注解式注入。

## §4 扩展面（工具 · 插件 · MCP · 连接器）

### 4.1 三层分离 + 执行管线（RD/管线语义）

| 层 | 职责 |
|---|---|
| **工具契约** | 给模型看的接口：名称/描述/参数 schema/权限档/危险级别/**缓存影响声明** |
| **工具注册表** | 唯一入口：装配 · 裁剪 · 审批 · 并行安全 · 超时 · 输出上限 · 审计。**只在这里实现一次** |
| **执行后端** | 真正干活且可替换：文件/命令/沙箱/网络/数据库/远端服务 |

**执行管线五级（引用归档侧实证，见 §16）**：`pre-execute`（可扩展 allow/deny/ask）→ **注册的单调 guard** → `execute`（环绕分发）→ `post-execute`（检视/替换/附带上下文）→ 定义自有的 `finalizeContent` → 只读观察 `result`。
**不变式**：**guard 单调 = 已返回的拒绝，后续监听者不得翻案**（deny 不可被后来者改回 allow）；本条是"工具层围栏"（§7.2 第 3 层）有确定语义的前提。

### 4.2 五类来源（都进同一注册表）

| 来源 | 怎么进 | 谁负责 | 沙箱/围栏 |
|---|---|---|---|
| 自研工具 | manifest → 装载器注册 | agent 运行时 | 引擎沙箱 |
| 连接器暴露的能力 | 经平台连接器网关（也可经 MCP 注册） | 平台 | 平台 + 引擎沙箱 |
| 插件 | manifest（`capabilities` + `denied_by_default:true`） | 平台 | **插件用 WASM/容器，与 agent 沙箱不互换** |
| MCP 外部服务 | 适配器把外部工具注册进同一注册表 | agent 运行时 | 引擎沙箱 + 网络出口 |
| **外部引擎原生工具** | 保留（不剥夺），用沙箱 + 命令策略围栏（RD-01） | 引擎自己 | 四层隔离（§7.2） |

### 4.3 manifest 与装载

- manifest 字段：名字、描述、参数 schema、权限档、危险级别、所属连接器、版本。
- 装载器：启动时读全部 manifest → 注册成工具清单 → 按**平台既有裁剪链**裁剪（**公式与现网口径以《总方案》§8.5 为准；本文不重写**）。
- **迁移策略：一次性声明化，不分批**。
- 验收：加/删一个工具 **不改核心代码、不整体重启**（`RA-03`）。

### 4.4 审批 · 并行 · 超时（**P1 重写为两层 + 三态**）

**审批＝两层 + 一个特例**：
1. **全局审批策略**（会话/运行级）：四档 —— `on-request`（默认，越沙箱才问）/ `unless-trusted`（基本都问，规则覆盖的除外）/ `never`（不问）/ `on-failure`（先沙箱跑，失败才问）。【核实官方文档】
2. **规则清单**（命令/动作级）：每条规则声明 `decision = allow | prompt | forbidden` + **理由**，并**自带 `match` / `not_match` 用例**；**加载即校验**（规则语法/用例失败则拒绝装载）；**在沙箱之前评估**。【核实官方文档】
3. **特例**：MCP 服务器可另按**服务器**与**按工具**声明审批模式（`default_tools_approval_mode` / 每工具 `approval_mode`）。

**并行安全**：按工具/来源声明"是否可并行"。
**超时（`RA` 语义要写清）**：超时字段**只是声明，不等于生效**；必须区分三态 —— **① 已中止 ② 已超时但工具仍在跑 ③ 未超时**。**硬停需要进程组取消，归执行后端（§6.2）**；协作式超时必须如实上报"仍在跑"，不得假装已停。

四档权限（只读/读写/需审批/完全）＝**会话级粗粒度**；本节＝**工具级细粒度**，两者是层级关系不是重复。

### 4.5 MCP 双向

既用别人的 MCP（把外部工具注册进注册表），也把 RW 暴露成 MCP server（给别的 agent 用）——**后者的反向暴露是 M2 交付项，《引擎改造计划》§7.1 ⑭，M1 不做**。原则：**一个内核 + 多个适配器**。

### 4.6 文件写读一致性（B7，采纳为纪律）

文件写/编辑前必须**先观察**：① 未读先改 → 拒绝（稳定错误码）；② 读后被他人改动 → 拒绝（稳定错误码）；③ **观察态不跨 resume**（恢复后需重新观察）。

## §5 上下文面（成本的主战场）

### 5.1 一条总原则

> **上下文是花出去的钱，不是"信息越多越好"。判据：这一段不进上下文，agent 会不会做错？不会，就别放。**

### 5.2 五层按"稳定度"排序（顺序同时是钱与信任边界）

| 层 | 内容 | 何时变 | 放哪 | 可信度 |
|---|---|---|---|---|
| 系统层 | 岗位包生成的身份/职责/边界 | 只随版本变 | 最前 | **可信** |
| 工具层 | 工具清单（已按权限过滤） | 只随权限变 | 紧接系统层 | **可信** |
| 知识层 | 检索到的知识、技能 | 每次不同 | 中段 | 不可信 |
| 任务层 | 本次任务/目标/交付物结构 | 每次不同 | 中段 | 半可信 |
| 结果层 | 工具返回 | 每次都变 | 最后 | 不可信 |

**三条纪律**：① 最稳定放最前；② 不为了让提示"看起来完整"而加东西；③ **每次请求的系统层 + 工具层必须逐字节一致**（同版本岗位包 + 同权限）——不一致就是漏了（`RA-38`）。

### 5.3 前缀五条纪律 + 前提与计量口径

**实测结论**（本对话会话 3032 次请求）：命中 1,340,696,704 / 未命中 3,819,230 = **99.72%**；中位单次 99.94%；**未命中的 41.4% 只来自 12 次请求**。失效四类：首轮、**切模型（命中归零）**、长空闲（小时级）、**工具 schema 变更（单次 574,865 tokens）**；折叠边界短暂掉到 74–84%，1–3 次恢复。

| # | 纪律 | 现状（待改造） |
|---|---|---|
| 1 | **只追加**：不改写早期消息；折叠只在段边界整段替换一次 | ✅ **已落地（步3）**：删除了每轮改写前缀的 `archiveEarlyContext`；折叠保留为段边界整段替换并记 `[collapse]` 归因 |
| 2 | **前缀冻结**：系统提示会话内不变；技能/知识/目标/时间/快照进"尾巴区"；变更**追加为 in-history 节点** | ✅ **已落地（步3）**：目标/技能/知识/断点现场/只读意图/高成本自荐六类迁至 hist 之后；签名等仍需（in-history 追加未做，当前走"尾巴区"） |
| 3 | **工具面会话内冻结**：MCP 装载/改档位/换壳＝**新段**并提示"会重建缓存" | ✅ **已落地（步3）**：`defs`/`toolsHash` 提到 `runAgent` 开头，一次运行只算一次；"新段提示"待步8 |
| 4 | **增量最小化**：大结果一律溢出 | ✅ **已落地（步6）**：超内联上限（4000 字符／子代理族 12000，且 32768 字节）→ 全文落盘 + 上下文"头 60% + 尾 30% 预览 + 精确省略量 + 定位符"；`fetch_spill` 按范围取回；**存盘失败不改工具成败**（降级为内联截断 + 如实提示） |
| 5 | **失效可数 + 声明契约**：失效事件是一等观测指标；**任何进入前缀的组件必须声明缓存影响** | ✅ **计数仪表已落地（步5）**：C5 归因（`prefix:exempt`：首轮/长空闲/切模型）、C4 机检落账（`prefix:invalidate`）、折叠归一（`prefix:collapse`）＋ `scripts/baseline-cost.mjs` 出 C1–C5 报表；**机检上线至今 C4 = 0**。"缓存影响声明"契约仍待补（组件级声明未做） |

**纪律 2 的前提（必须写进实现）**：in-history 追加**只对"支持该能力的模型路由 + 同一请求序列"成立**；模型网关必须声明 `supportsInHistoryPromptUpdate`；不具备该能力的路由，只能**替换头节点**（一次全量失效）并**如实记录**，**不得静默按 in-history 处理**。

**计量口径（RD-13）**：C1/C2/C4 **以 provider 上报为准**（缓存读/未命中/输出三类）；启发式估算（如 4 字符/token）**只用于事前压力预测，且必须标注为预测**——它**会显著低估中文与 JSON schema**，而那是我们的主场景。

指标口径（C1–C4、C5）以《引擎改造计划》§0.3 为准；**单独的"命中率"会掩盖浪费**。

### 5.4 工具结果处理：两个不同时刻（**别混 + 单位不同**）

| | **溢出 spill** | **修剪 prune** |
|---|---|---|
| 时刻 | 工具刚返回时 | 折叠会话时 |
| 动作 | 太大 → 全文存盘 → 上下文只留"头尾预览 + 定位符" | 历史旧结果 → 掐中段留头尾 + 插标记 |
| 取值 | **已实现（步6）**：触发 = 超内联上限（**4000 字符**，子代理族 **12000**；**且 32768 字节**，两者取先到者）；预览 = **头 60% + 尾 30%**（按 Unicode 码点切）；定位符三态 = 源文件（读取类，`read` 不复制落盘）/ 溢出文件（`<工作区>/spill/<会话>/…`）/ 降级提示（存盘失败，**不改工具成败**）| 阈值 **8192 字符**、头 **4096**、尾 **1024**（**4:1**，实读对方源码核对）；标记固定；**回放安全**：追加一条 prune 事件记录被替换节点（我方当前**未实现独立 prune 阶段**：工具结果在入口一次定型，折叠负责早期轮次） |
| 取回 | `fetch_spill {path, offset, length}` 按范围取；**路径围栏**限定溢出目录内 | —— |

**单位不可比**：spill 触发与省略量按**字节**报送、上限按**字符**判定（UTF-8 计）——中文场景下"4000 字符 ≈ 12KB"，会先撞字符上限；子代理族 12000 字符 ≈ 36KB 时才轮到 32768 字节的天花板生效。**两个阈值不得直接比较或互相换算成"4 倍关系"。**

**提示格式（已实现）**：`…[已省略 <N> 字节（<M> 字符）；<定位符>]…`——**字节与字符都给**，**带精确省略量，让 agent 知道自己不知道什么**；落盘成功时定位符后附 `fetch_spill {path:"…", offset:0, length:20000}` 取回指引。

### 5.5 折叠（=压缩，全文统一用"折叠"）

`thresholdRatio 0.8`（模型窗口 80% 触发）· `retainRatio 0.16` · 摘要输出上限 8192 tokens · 重试各 1 次 · 在**步边界**自动触发（数值均实读对方源码核对）。**绝对值换模型就失效，比例制才跟着窗口走。**

**三条增强（P1/P2 采纳）**：
1. **摘要请求必须逐字节重放被折叠区间的原请求前缀**（系统提示 + 上次路由的工具面 + 被遮蔽区消息）——这样只有尾部指令与摘要输出是未命中，**避免为折叠再付一次全量输入**。
2. **逐 `provider × model` 策略覆盖表**：`thresholdRatio` 与 `retainTokens`（绝对值）**互斥**，且 `retainTokens` 必须小于该模型阈值（否则在该模型首次使用时报错）；**摘要可路由到廉价模型**。
3. **绝对不能折**：交付物的依据 · 审计需要的信息。折完两份都留：**摘要进上下文，原始轨迹入审计**（`RA-40`）。
4. **折叠必须留够工作集（步5 实测，已落地）**：保留条数有**下限 10**——实测 `keep=1` 时每轮折叠都把"本轮任务 + 近期工具结果"一并折掉，模型反复失忆、重复探索，**58 轮 / 112 次工具调用仍不收敛**；低于下限按 10 生效并**如实告警**。折叠参数是"能省钱的旋钮"，但**不能旋到把会话旋死**。

### 5.6 按需召回（四件，替代"预先塞"）

| # | 从 | 改成 |
|---|---|---|
| 1 | 技能全文进系统提示（单技能 ≤1.6 万字符） | 系统提示只放**技能目录**，用时调"加载技能"工具 |
| 2 | 每轮自动注入 12 条知识 | 给"**查知识**"工具，需要才查 |
| 3 | 结构化数据靠"记" | **连接器精确查询**——**不进上下文、不进向量库** |
| 4 | 项目说明（AGENTS.md 类，≤1.6 万字符）每轮注入 | **只在与本次任务相关时注入**（落任务层） |

**检索策略**：先全文（FTS5）打底，向量**留接口位置后补**。
> **口径统一（P1）**：检索口径**以本节为准**；《引擎改造计划》§4.3 中的"语义检索"为旧措辞，已同步改为"全文检索打底"。

### 5.7 注入防御（顺序即信任边界）

三层：**来源标注** · **信任分级**（外部内容**不能改写系统指令**）· **结构隔离**。
> 核心：不要指望"在提示词里告诉它别听外面的话"——要让外部内容在结构上就没有资格当指令。

**两条必须落地的工程手法（P1 采纳，机制与 owner 见 OP-11）**：
1. **来源框架的字面转义**：外部内容里出现的框架闭合标记必须转义，使"仓库/工具可控的文本**无法闭合我们自有框架**"。
2. **大文件只进句柄、永不进字节**：非文本附件进上下文的是"文件名 + 字节数 + 摘要前缀 + 只读路径"的一行句柄，模型**从不收到原始字节**。

⚠️ **一条硬约束**：**禁止把"上次工具返回的内容"写进系统层或知识层**（可信区被污染）。须由平台侧机制堵死，不能靠 agent 自觉。

### 5.8 权限过滤在进上下文之前

agent 拿到的工具清单**已按权限过滤**——没权限的工具**根本不出现在清单里**（不是"出现了但调用会被拒"）。**拦的那道可能被绕过，看不见的没有绕法。**

## §7 保障面

### 7.1 权限与结束裁决

四档权限（§4.4）+ 两层审批（§4.4）；**结束原因**（完成/放弃/超预算/出错）由平台裁决；对外调用**必须异步**（§9.3）。

### 7.2 隔离：四层 + enforcement 三值（**RD-15 重写**）

```
第 1 层  环境隔离（gVisor / microVM）      ← 平台：防逃逸、跨租户、跨项目；⚠️ 挡不住 curl
第 2 层  引擎自带沙箱（read-only / workspace-write / danger-full-access） ← 引擎：防本环境内越界写
第 3 层  工具层围栏（文件与 shell 同根目录；命令策略在沙箱之前评估，见 §4.4/§4.1 单调 guard）
第 4 层  网络出口（默认全断 + 白名单代理 + 全过代理可审计）  ← 平台；⚠️ 前两层都覆盖不到
横切：  检测（逃逸/异常/外泄信号）
```
**沙箱五条不变量**：一次运行 = 一个沙箱 = **用完即毁** · 沙箱内无长期凭据 · 数据"**不存在**"而非"不许看" · 不能提权 · **交付物是唯一出口**。

**失败语义（取代原"同层/跨层"，因为原判据不可判定）**：
| 情形 | 处置 |
|---|---|
| 第 2 层**拿不到模式 / 自检不通过** | **拒绝启动**（fail-closed），不降级运行 |
| 第 1/3/4 层**能力缺失**（客户环境不支持） | **显式降级**：如实上报 + 留痕 + 提高审批等级 + 客户可见（OP-16）；**禁止静默降级** |
| 降级后实际约束范围不足 | **逐次调用如实上报 `enforcement: full | partial | none`**，UI/接口必须显示 |

**升档（escalation）**：只允许**封闭梯子**（read-only → workspace-write｜danger-full-access；workspace-write → danger-full-access）；每次升档**单次批准**且必须带 **justification**（批准与理由成对校验）。

**Windows 平台事实（P0-3 更正）**：Codex 的 Windows 沙箱用 **restricted tokens + job objects**，官方**支持 elevated 与 unelevated 两种模式**，**未标注实验性**（被标 experimental 的是 **Linux Bubblewrap** 管线）。「Everyone 可写目录 / 硬链接别名」是 **DS harness 自己的 partial 免责声明**（其 `windows-acl` 档位即 `partial`）——**不是 Codex 的官方声明**。→ 一期"客户内网 + Windows Server"**不需要白造一套沙箱**，而是**如实声明 partial 并靠第 4 层网络出口与审批补齐**。

**成本关键**：**等人复核时沙箱必须销毁**——否则"成本曲线被人的响应速度决定"。运行可以等人，沙箱不能等。池化/预热**只在出现实测数据后才评估**，当前不做。

### 7.3 数据视窗：唯一出口链

```
数据源 → 视窗裁剪（行过滤 × 列规则 × 聚合规则） → 物化（工作文件／只读挂载／只读查询接口）
       → 沙箱内 agent（它的原生工具读到的就是裁剪后的值）
```
**数据源侧三类入口（连接器／物化工作文件／只读查询接口）全走这条链。**
三条铁律：① **视窗在数据出口生效**——不是"看到了但被告知别说"；② **禁止用提示词替代数据视窗**；③ **子代理视窗只能比父级更窄**。
**这条把数据视窗从"agent 看不看得见"变成"沙箱里有没有"——物理隔离，不是君子协定。**

**双投影接缝（RD-14，采纳）**：**裁剪/溢出/折叠只作用于"模型可见副本"**；**durable 记录（审计/回放）保留原文**。附带说明类内容**不得替换工具结果本身**（如提醒只作附加上下文，`tool/result` 事件保持工具原输出）。
⚠️ 前置缺陷：数据出口在旧文档里"四处指向不同组件"→ 本裁决要求平台数据面落地前**收敛为这条唯一链**（OP-01）。

### 7.4 凭据

**凭据不进沙箱**：连接器凭据留在平台侧，agent 只有工具、没有钥匙。`--yolo` 类逃生门（`--dangerously-bypass-approvals-and-sandbox`）**必须在调用层参数白名单封禁**，不允许透传。

### 7.5 状态恢复（三种中断 + 崩溃安全事务括）

| 中断原因 | 能否继续 | 怎么继续 |
|---|---|---|
| 人主动打断 | ✅ | 接着跑，上下文还在 |
| 预算耗尽 | ✅ **但要追加预算** | **不能自动续** |
| 系统故障 | ✅ | **从检查点重建** |
| 策略拒绝/越界 | ❌ | 不恢复，人工处理（**可能是安全事件**） |

**检查点存**：上下文摘要 / 已完成到哪一步 / 已产出的交付物 / 剩余预算。**不存**：沙箱状态 / 沙箱内临时文件 / 内存凭据。
⭐ **恢复 = 重建一个干净沙箱 + 重放上下文摘要**，不是"把沙箱恢复回来"。
**崩溃安全事务括（B8，采纳）**：折叠/迁移这类多步写操作必须**记一个"进行中"标记**（开始事件同步落盘，结束事件收尾）；**未闭合的开始标记＝持久锁**，重启后据此判定并恢复，**不依赖"进程还活着"**；收尾**只尝试一次**，失败则**故意留下阻塞性孤儿**以便人工判定。

### 7.6 预算与循环

- **四种预算同时管**：token · **钱（最硬）** · 步数 · 墙钟；总量与裁决归平台。
- **软着陆三档**：70% 提示收敛 → 85% 换便宜模型收尾 → 100% **优雅中止并保留部分结果**。
- **循环检测 `[3,5,8]` 分级提醒、不熔断**（数值为**实读对方源码核对**，非我方实测）；参数比较需**深度 key 排序后**再比；提醒**不得阻止调用**（`RA-39`）。
- **前置条件**：不熔断必须先有软着陆兜底；软着陆未落地前，保留"连续失败挂起"作为过渡。

## §8 编排面

### 8.1 主循环

想 → 做 → 看 → 再想；每轮做**完成度判断**；**保留**既有护栏（轮次/时间/循环/连续失败、并行工具、真流式、外部停止）。

### 8.2 子代理：价值是"上下文隔离"，不是"能力增强"

| 该用 | 不该用 |
|---|---|
| 能并行的独立调查 | 简单任务（拆了更贵） |
| 需要大量试错、只要一个干净结论 | 需要共享大量上下文的 |
| 需要一个"不同性格"的执行者（挑错的审查者） | 单线程线性任务 |
| 上下文会爆炸必须隔开 | —— |

### 8.3 四条硬约束

① **权限 ≤ 父级**（通常严格小于）· ② **预算切分不共享** · ③ **深度限制**：默认 **2 层**（RD-04），岗位包可收紧到 1 · ④ **结果收敛**：只回结构化结论，**不回传原始上下文**。

### 8.4 统一接口：**按 provider 注册表**（RD-10 / B12 重写）

```
派活(任务说明, 上下文切片, 预算额度, 权限子集)
  ↓
结论(结构化结果, 消耗了多少, 用了哪些能力, 结束原因)
```
实现形态：**一个 provider 注册表，多家后端并列**（自研 in-process / ACP / SDK / Codex / 其他 harness）。
**四条硬要求**：① **能力广告**：每个 provider 声明自己支持什么（含是否支持工具面定制、事件流、结构化输出）；② **能力缺口显式拒绝**：请求需要的能力该 provider 没有 → **启动即显式失败**，不得静默忽略；③ **失败回滚**：启动失败要回收已分配资源；④ **目录事实**：成功的子代理要在父会话留下可审计的"目录"记录。
**Codex 转译注意（P2）**：其非交互退出码为 `0 成功 / 1 一般错误 / 2 认证失败 / 3 配置错误 / 4 模型或 API 错误 / 130 被用户中断`——适配器**必须区分"认证失败"与"任务失败"**，否则会把"客户 key 过期"记成"agent 没干成"，污染成本基线与诚实性判定。

### 8.5 预算切分四条

切出去的是**额度不是共享池** · **父级必须留一部分给自己** · 没花完的**显式回收**（不自动回流）· 按**复杂度**分，不平均。

### 8.6 与平台的分工

岗位包**声明**编排模板（并行/串行/混合、用哪些连接器、产出、汇总方式）→ 平台**拆解 + 权限收缩 + 预算切分 + 并发调度 + 回收 + 汇总 + 审计** → agent 只提供"**跑一个子代理**"。**模板与调度的完整定义以《总方案》与平台侧为准，本文不重写。**

### 8.7 触发器接口

引擎只提供标准接口（手动 / 定时 / 外部调用 / 事件）；**调度实现归平台**。**别把定时任务塞进会话**。**已在自研（`server/scheduler.js`）。**

**文件交付统一走平台的送达服务**：agent **只提交引用，不直接给文件**（避免绕过送达与审计）。

## §10 诚实性机制（RW 独有资产，必须保留）

## 附录 A · 术语

| 术语 | 定义 |
|---|---|
| **引擎 / 运行时** | 引擎＝"思考"部分（可换）；运行时＝"干活"部分（自研资产） |
| **骨架** | 让七面可替换/可声明/可演进的基础机制：服务注册与替换（显式工厂+接口+单一注册点）、契约与协议、声明式配置、不变式（3 条机检）、确定性与可重放 |
| **工具 / 执行后端** | 工具＝给模型看的接口契约；执行后端＝真正干活且可替换的实现 |
| **围栏 vs 接管** | 围栏＝保留外部引擎原生工具 + 外围约束；接管＝禁用原生工具只注入我们的清单（本文取**围栏**） |
| **溢出（spill）/ 修剪（prune）/ 折叠（compress）** | 三个不同时刻的结果处理：工具返回时落盘留预览；折叠时掐历史中段；窗口压力时整段替换并留摘要 |
| **前缀冻结 / in-history 追加** | 会话内不改已发出内容的前缀；系统提示变更时作为新节点追加到已缓存历史之后（**有前提**，见 §5.3） |
| **确定性投影** | 同一会话任一时刻投影出的上下文一致（可重放） |
| **失效事件 / C1–C5** | 一次请求中"整段前缀作废"的事件；C1 整体命中率、C2 每轮新增、C3 单位成本、C4 非预期失效次数、C5 豁免失效（只报数） |
| **enforcement: full / partial / none** | 逐次调用如实上报的**实际约束程度**（替代不可判定的"同层/跨层"） |
| **四层隔离** | 环境隔离 / 引擎沙箱 / 工具层围栏 / 网络出口（+ 检测横切） |
| **数据物化 / 双投影** | 物化＝把裁剪后数据放进沙箱，使 agent"没有原始数据可读"；双投影＝**模型可见副本**与 **durable 原文**分开 |
| **岗位包** | 平台侧配置（owner=平台）；本文只消费 5 个字段（身份/能力/权限/运行环境/模型策略） |
| **新段** | 无 MCP/档位/引擎装配变更的连续会话段；工具面变更即开启新段（其首轮失效不计入 C4） |
