## 1. 目标与验收（用户确认的一句话）

**把 RW 封装成"无身份 Agent 核心"：壳主不改核心代码，写一份"壳定义"（身份/领域/工具/模型/知识/权限）→ 一键装配 → 该壳里的 RW 立即以壳的语境与能力工作，且对话/思考/工具/护栏/计量/审计全部照常。** 验收：克隆现有壳→改 5 处→10 分钟新壳可用（§5）。

## 2. 架构分层（行业共识的引擎/壳/运行时三层，RW 自托管版）

```
┌ 运行时面（现有 RW，基本不动）────────────────────────────┐
│ runAgent 循环 · 63 工具 · hooks/审批/审计 · 计量 · 驱动器 · SSE │
└──────────────────────────────────────────────────────┘
        ▲ 会话创建携带 shell_key；识别/路由结果作为注入
┌ 壳定义层 ★新增（本文核心）───────────────────────────────┐
│ shellpacks/<key>/pack.json（§3 schema，git 版本化，§4）   │
│   identity(可空=中性) · domain · modelPolicy · tools       │
│   knowledge · skills · guardrails · intentRules(②)       │
│   taskProfiles(③) · channels/uiBrand/eval                 │
└──────────────────────────────────────────────────────┘
┌ 决策小层 ★新增（薄垫片，不改执行链）───────────────────────┐
│ 意图识别（②）：每壳词表 → 标签(要动手·普通/高危/只读/闲聊/拿不准) → 灰字回显 │
│ 任务路由（③）：显式(C4 绝对锁) > 档案建议 > 壳默认 → 灰字回显     │
└──────────────────────────────────────────────────────┘
```

## 3. 壳定义 schema（①收口已定稿 v1；②③为 v1.1/v1.2 可选节）

字段集（详见 `proposals/RW可封装Agent-收口v1.md` §3）：
`shellPackVersion / key / name / description / identity(persona|null) / domain / modelPolicy{default, allowModels, budgetYuan, qualityCostBias 0-10} / tools{presetBase, forceOn, forceOff, mcps, connectors} / knowledge{scopes, importRefs} / skills / guardrails{accessRules, approvalMode} / channels / uiBrand / eval{goldenSetRef}`

- **v1.1 可选节** `intentRules`（②）：`do/highRisk/readonly/chatOnly` 词与正则 + 后置 `intentSamples`（纠错沉淀例句）；
- **v1.2 可选节** `taskProfiles`（③）：命名档案数组（见 §7）；
- 新增一律=新增可选节/字段（schema 版本号向前兼容），永不推翻 v1 已用字段。

## 4. git 版本化（①已定稿，§3.1）

`shellpacks/` = git 仓库；每壳一个目录；pack.json 为权威副本（diff/tag/revert/branch/push-pull/审计记 commit）；装配器落地为 DB 运行态（"文件=权威、DB=镜像"，与 hello 双写同构）；生效链路=commit → reload（policy_rev，最快 5s）→ DB 同步。渐进：档1 导出/导入 + 手动 git → 档2 文件为源+watch → 档3 多实例共享/版本钉住/PR 评审。

## 5. 装配流程与验收（①已定稿）

import(校验 schema+占位符检疫) → upsert 壳行/壳设置/壳工具三态 → 会话带 shell_key → 引擎按包执行（身份注入 persona 空则中性/知识过滤/技能白名单/工具面/模型解析/护栏）→ 冒烟 → 装配报告。验收=10 分钟克隆新壳可用（改 persona/forceOff/modelPolicy/domainHosts → 新会话验证语境/禁工具/模型/审计带壳 ID/中性壳回归）。

## 6. 意图识别（②已定稿 v1；v2 触发挂清单）

- **v1**：每壳词表（`intentRules`，默认壳保留系统兜底=现 `TOOL_INTENT_RE` 迁移）→ 输出标签：要动手·普通 / 要动手·高危（先审批）/ 只读规划 / 闲聊 / 拿不准就问（绝不假答应）；**意图回显**灰字（识别对错当场可见，纠正沉淀为 intentSamples）；LLM 兜底默认关。
- **v2（触发）**：考题集命中率 <90% 或"拿不准"频次高 → 开 LLM 兜底；再不够 → 加任务类型标签（供③自动匹配）。

## 7. 任务档案 + 路由（③，按我的建议纳入 v1，待随本方案整体确认）

- **档案=命名的"干法模板"**（壳包 `taskProfiles`，可克隆自定义）；v1 三要素：`name / match(用户点名·UI 选择；不自动猜) / modelHint{default, qualityCostBias}`；外加唯一工具特例：`toolsExtra.forceOff=[写类]`（保证"重构方案/只读规划"场景不改文件）。
- **预置示例**（code 壳）：small-fix（小修→便宜快模型）/ refactor-plan（重构方案→推理强+强制只读）/ feature-delivery（新功能交付→稳定模型）等。
- **三级路由**：①你显式指定模型（绝对锁，C4）> ②档案建议 > ③壳默认；决定后**灰字回显**（"任务档案：小修 → 建议 deepseek-v4-flash(质量3) · 可显式换"）+ 可一键退回默认。
- **观测位**：档案命中记审计（档案×模型×难度），只记录不展示（供⑤按档案维度分析）。
- **v2（触发）**：你常手动换模型/改档案 → 上"自动匹配档案"（接②任务类型标签或 LLM 匹配）。

## 8. 版本回补策略（本次讨论确定的机制，全局适用）

1. 每个议题分 **v1（基础，先做稳）** 与 **v2（完整，挂触发信号）**；v2 由"数据信号"触发而非时间表；
2. 常驻待办：**每两周 30 秒对照触发清单**（已挂待办任务）；到点由你决定是否回补；
3. 新能力默认关（LLM 兜底/自动匹配等不开不影响 v1 行为）；
4. schema 版本化+可选字段=完整版"加层加字段"而非重写；
5. 硬规矩：任何改动过 **selfcheck + 随壳包考题集(eval/ golden) + 880 E2E**，行为变化先被测试发现。

## 14. ④⑤⑥ v1 收口增补（2026-09-08 用户批量确认；⑤指标不含自测）

### ④ 知识库 v1（L2）
- scope 三级：global / shell（随壳包 git 版本化）/ project（预留）；默认"壳私有 + 全局共享"两级；
- 上传链：UI 拖拽 → /api/upload → extract_* → 入库；**xlsx 按行结构化优先**（物料/价格表可查）；
- 检索=关键词 + 命中溯源（原文摘录+所在文档/行）；shell 知识仅该壳会话可见；
- v2（触发）：向量检索用**服务器自托管开源 embedding**（bge-m3 等，数据不出服务器；资源不足则继续 L2 不开）。

### ⑤ 模型观测 v1（观测式，指标锁定：不含自测）
- 每次执行落 `(执行模型 × 难度估 × 任务档案)`；
- **指标集（用户确认）**：一次通过率 ／ bug 数（打回必填原因）／ 任务时长 ／ token 消耗 ／ 费用消耗；（可选"自测通过率/打回原因分类标签"——本次**不加自测**，原因标签后置可议）
- 展示：壳内"模型观测"页（卡片趋势 + 逐任务流水可下钻会话与打回原因）；
- 与③联动：观测异常仅**提示建议换模型，不自动改路由**；观测同时是 v2"自动匹配档案"的触发数据源。

### ⑥ 任务资产市场 v1
- 资产单元=模板包（三件一体）：taskProfile（③）+ 技能 SKILL.md + 验收模板(DSL) + 说明；
- 存放=模板库目录随仓库 git 版本化（复用 export/import、apply-pack 机制）；
- 入口：壳内"从模板开任务"（③选档案时可浏览）+ 统一后台模板库（后置）；不做商店审核/分成；
- 首批模板=code 壳预设（小修/重构方案/新功能交付/意图词表）+ 业务壳调教回流。

### 本地模型部署（新增观察项，2026-09-08 用户提问引出）
- DeepSeek 等开源大模型**可以**自托管（下载权重在服务器跑），与 embedding 小模型是两类用途（对话/推理 vs 向量化）；
- RW 厂商层本就是 OpenAI 兼容可插拔 → 本地部署 = providers 加一个 base 指向本地服务（Ollama/vLLM），壳/档案照选；
- 价值：免 API 费（换硬件/电费）、更强数据边界（连对话都不出服务器，契合企业壳）；门槛：显存/内存/并发/运维；
- 是否值得、跑哪些模型/量化档、与云 API 的搭配 → 列为独立观察项，待硬件与用量账目清楚后再评估（不进 v1.1 实施批次）。
