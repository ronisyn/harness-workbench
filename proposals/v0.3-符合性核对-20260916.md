## 2. 三块"从零开始"的量级：要做什么（含 DSH 对照）

### 2.1 ⑦ 存储抽象（P1，依赖 ①）

**DSH 怎么做**（先问规矩）：**接口包 + 实现包**分层，靠配置选实现——
`dsh-storage`（接口）/`dsh-storage-domain`（领域）/`dsh-storage-json`（实现）；
会话侧 `dsh-session-persistence`（接口）+ `dsh-session-persistence-jsonl`（实现）；
查询 `dsh-session-query`（接口）+ `dsh-session-query-sqlite`（实现）。

**我们要做什么**（分批，不是一次改 379 处）：
1. 定**存储接口**（读/写/事务/查询四类动词）+ 现有 MySQL 实现（把 379 处逐步收口到接口后面）。
2. 定**第二个实现**才有 G1（"不依赖我们的数据库"）：最轻的是 SQLite/JSON 本地实现（对应 DSH 的 `-json`/`-sqlite`），

2. 把散落的"平台面"逐个归到后端：命令（已有）、文件写入语义、进程终止（已有 taskkill 分支）、服务/重启（已有 `RW_RESTART_CMD`）、

### 2.3 ⑰ 沙箱服务与分级（P3，依赖 ⑯）——本篇最大的一块

**v0.3 的要求（原文口径）**：§4.6「沙箱：服务 + 按平台后端」；失败语义以老文档 **RD-05/RD-15** 为准：
**第 2 层（引擎自带沙箱）拿不到模式 → 拒绝启动**；第 1/3/4 层能力缺失 → **显式降级**（留痕 + 提高审批 + 客户可见，
禁止静默降级）；降级程度逐次上报 `enforcement: full/partial/none`。§0.2 G1 要求"**沙箱可替换**"。

**DSH 怎么做**（可直接借的骨架）：
- 分层：`dsh-sandbox`（服务/接口）+ `dsh-sandbox-policy`（策略）+ `dsh-sandbox-local`（本地实现）+
  **`dsh-sandbox-windows-acl`**（Windows 专用后端）+ 按子系统分的适配器 `dsh-fs-sandbox`/`dsh-bash-sandbox`/`dsh-pwsh-sandbox`。
- 平台 runner 链：Linux **`bwrap` → `landlock`**（addon `landlock-run`）、macOS **Seatbelt（`sandbox-exec`）**、
  Windows **ACL 受限令牌 runner**；**每个 runner 都做"功能性探针"**（真起一次、真跑 `true`/`--mode` 校验），
  结果有界缓存；全部不可用 ⇒ `SandboxUnavailableError(mode)`（**拒绝执行**，不是静默放行）。
- 模式词汇：`read-only` / `workspace-write`（与我们 `permission` 的 read/write 对齐）；
  还有 workspace 授权 + **每会话随机私有临时目录能力**（可撤销）。

**我们要做什么**（六件，按依赖排）：
1. **策略**：把现有 `permission`（read/write/full）+ `RW_WORKSPACE`/`RW_FS_ROOT` 映射成沙箱模式
   （read→`read-only`、write→`workspace-write`、full→**不沙箱但要如实降级上报**）。
2. **服务与后端接口**：`server/sandbox.js`（探针 + 选择 + 报告）+ 后端实现（Linux `bwrap`/Landlock、Windows ACL/Job Object）。
3. **功能性探针 + 启动门禁**：启动时探测第 2 层；**拿不到模式 ⇒ 拒绝启动**（现在零命中——这是 §4.6 里唯一带"硬门禁"的一条）。
4. **降级目录与上报**：`enforcementReport` 由**硬编码常量改成探测结果**，并落到 `DEGRADE_CATALOG`；
   经 `capabilityManifest`/`GET /api/agent/capabilities` 对客户可见；`run_end` 逐次上报（已有位置）。
5. **提高审批**：把"处于降级态"接成**审批触发条件**（`approval.js`/`asks.js` 队列已有，缺触发接线）。
6. **持久账本行**：每次降级/失效落一条账（现在只进事件与 HTTP 清单，没有独立账本行）。

**现有机制能承担的部分**（不要重造）：`capabilities.js` 的三值语义 + 四层结构 + `DEGRADE_CATALOG`（声明与出口齐）、
`hooks.js` 的 fail-closed 与留痕（`hook:error/timeout`）、`approval.js`/`asks.js` 的队列、`credentials.js` 的脱敏兜底。
**缺的**：真隔离（第 1/2/4 层）、探针、拒绝启动的挂点。
