## 步骤 5 · C1–C5 仪表落地 + 折叠路径取证（2026-09-15）

- **改了什么**（全部落在现有载体上，**不新造表、不新造指标系统**）：
  1. **C5 豁免归因**（`agent.js`，运行起点只算一次）：查本会话最后一条 `usage_stats`，分类 `first-round` / `idle:Nmin`（间隔 ≥ `RW_IDLE_MIN`，默认 60）/ `model-switch:A→B`，命中则落 `audit_log(action='prefix:exempt')`。
  2. **C4 机检落账**：前缀不变量断链且**非折叠轮次** → `audit_log(action='prefix:invalidate', detail='first-diff-idx=…')`（此前只有日志行，现在可统计）。
  3. **折叠可数**：折叠发生 → `audit_log(action='prefix:collapse')`；C5 的折叠边界只报数、不设 0。
  4. **`scripts/baseline-cost.mjs` 扩展**：C1–C4 报告 + 失效账本（`prefix:*` 分组、C5 归因 top6、C4 明细 last5）。
- **两个真 bug（自检发现，当场修）**：
  1. **`agentLimits()` 静默回退**：`failPick` 定义在 `try` 之外却引用 `try` 块内的 `const rows` → **必然抛 `rows is not defined`** → 被裸 `catch` 吞掉、**所有 settings 护栏阈值一律回退默认值**（"折叠阈值设了不生效"的真凶），且无任何日志。修：用同语义的 `pick` 取代 `failPick`；`catch` 改为 `console.warn('[limits] 读取护栏失败，已回退默认值：…')`（不再静默降级）。
     → 修后实测 `[limits-debug] {"gap":1,"keep":1,"trig":1}` **＝设置值**，阈值真正生效。
  2. **折叠保留条数无下限 → 会话不可收敛**（`keep=1` 实测）：探针会话 542 在 300s 内跑 **58 轮 / 112 次工具调用**（`db_query×76 · list_dir×22 · kb_search×14`）**仍未收敛**——每轮折叠都把工作集折掉，模型反复失忆、重新探索。修：`COLLAPSE_KEEP_MIN = 10` 下限 + 低于下限**如实告警**（`[limits] collapse_keep_msgs=1 低于下限 10，已按下限生效`），`settingsSchema.js` 提示同步标注下限。
     → 修后同一探针：**4 轮 / 3 次工具调用 / 6s 收敛**（对照默认阈值 4 轮 / 3 次 / 7s）。
- **验证（可照抄的取证命令与实测输出）**：
  - 默认阈值探针（conv 543）：`LLM轮=4 工具事件=3 折叠=0 耗时=7s`；日志 `[prefix-debug] core=1→3→5→7` 纯追加、`sys=bc39a145ff6b`/`tools=58c929e998eb` 逐轮同哈希、零 `[prefix-invariant]`。
  - 折叠账本（conv 542，未加下限时的 keep=1）：`prefix:collapse round=1 … round=59`，**同时 C4 = 0**——折叠轮次的断链被正确归因为"预期失效"，未误报非预期改写。
  - **`prefix:invalidate` 全表 = 0 行**（机检上线至今，含全部探针与自检流量）。
  - 基线复跑（`node scripts/baseline-cost.mjs`，同一把尺）：C1 全量 **12.53%** / 近 7 天 **25.37%**；C2 近 7 天中位 **22,007** / P95 87,904；C3 **¥2.84/run**、¥4.27/会话、累计 ¥255.90；C4 近似（整段作废候选）**47**。
  - 回归：`selfcheck` **12/12**、`final-e2e` **57/57**、服务 `active`；临时开关（`RW_PREFIX_DEBUG`、`RW_IDLE_MIN`）已从服务器 `.env` 移除并重启复验。
- **诚实说明**：
  1. **C1/C2 与基线几乎一致属预期**：基线以改造前的历史数据为主（2,762 行里绝大多数是改造前产生），改造效果必须用**改造后的新流量**才能度量——同一脚本复测即可。
  2. **两种 C4 口径并存、不可混用**：`47` 是"整段作废候选"的**历史近似**（粗）；`prefix:invalidate` 是机检上线后的**实测精确计数**（当前 **0**）。引用时必须写明口径。
  3. **失效账本是按事件追加、不随会话删除清理**：探针 542 在客户端超时后服务端仍在继续跑，清理动作之后仍补写了一条 collapse 行；`selfcheck` 的临时会话也留下 2 条 exempt 行（三行对应会话均已不存在）。因此**引用计数时应结合"会话是否仍存在"或按时间窗口取数**。
