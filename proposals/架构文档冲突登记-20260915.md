> 而不是先造好等它来（这也是本轮反复用的那条原则：不发明、不打补丁、简单优先）。

| 项 | 归属 | 为什么现在不做 |
|---|---|---|
| 存储抽象（DSH 有 storage 层） | M2 | 触发条件是**客户形态确定**（本地部署 / 多租户 / 云）；现在只有一种部署，抽出来就是空转的间接层 |
| fs / exec 后端抽象 | M2 | Node 的 fs 本身跨平台；**只有命令执行是 OS 绑定的**，而 §7.2 已拍板不为客户形态造沙箱。第二个后端（Windows 原生 / 远端执行）出现时再抽 |
| 沙箱策略 | M2 | 同上（§7.2 的决定）；`RA-27` 干净沙箱不可测 |
| 访问形态：headless / CLI / JSON-RPC / **MCP server** | M2 | `package.json` 的 `bin` 为空、`server/mcp.js` 只是**客户端**。对应 `RA-41`（被别的 agent 当工具调）与 `RA-42`（幂等键/回调 HMAC/死信落点），都在 M2；且一旦要做，先看 DSH 的对应形态再定契约 |
| 三家引擎成本基线 / AgentAdapter 契约 | M2/M3 | `RA-32`/`RA-33`：当前只有单一引擎的真实流量，基线与契约都要真实数据支撑 |
| 确定性投影的**运行时读**（不只是对账） | 下一增量 | 本轮先把账本与投影/对账做出来（RA-47 + 投影器）；让运行时改读投影，要先有"投影与现值长期一致"的证据 |
| 事件账本归档器的**自动化周期** | 后续 | 本轮实现归档函数与接线；真正的周期与容量参数等真实增长数据（不预设） |

## 已决：技能注入不再作废前缀（原"一处需要你拍板的取舍"）

**决定：A（改实现）**——`skill_load` 的技能全文改注入**尾巴区**（追加到历史之后），系统提示保持逐字节冻结。
理由：规则 2「前缀冻结」比规则 3「工具面冻结」更硬（前者影响**所有**会话，后者只影响当前会话），而技能是会话内行为。

**已落地并有证据**（2026-09-16 核对，声明与实现一致）：
- `server/prefix-participants.js` 的 `skill-load` 已标为 `where: 'tail'` / `cacheImpact: 'tail-only'`（原为 `breaks-prefix`）；
- 两条路径都是追加：开跑前由 `server/index.js` 推进 messages（锚点 `【已载入技能: `），运行期由 `server/agent.js` 的 `appendNewSkills()` 推在**工具结果之后**（锚点 `const appendNewSkills = () => {`）；
- 角色仍是 `system`（权威性不变），它前面的历史照样命中；
- 机检：`test/prefix-participants.test.mjs` 核对锚点还在 + 节点 0 只有一个写入点。

代价（如实）：技能在历史之后，模型对它的"权重"略降；这条取舍已被接受。
