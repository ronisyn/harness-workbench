## 1. 总体架构

```
浏览器 / 微信 / 飞书
   │ 域名: code.ronisyn.com / scm.ronisyn.com / 880 IP
   ▼
nginx（server_name → 同 upstream，透传 Host / X-Shell）
   ▼
RW 核心进程（现有单进程，机制零改动地复用）
   ├─ 壳解析层 ★新增：Host/渠道 → shell
   ├─ 会话（conversations.shell_id）
   ├─ 组消息注入：壳 persona/AGENTS → 技能/知识按壳过滤 → default_models 按壳
   ├─ runAgent（现有循环不变，ctx 增 shell 维度）
   ├─ 工具面：preset ∩ 账号启用集 ∩ 壳三态启用集
   └─ 计量/审计/驱动器：usage/audit/tasks/contracts 全部带 shell_id
统一后台（同进程，admin 角色）：/api/shells CRUD + 克隆 + 勾选 + 用量 + 导出 instance-pack
```

核心原则：**执行链不动，壳是"入口路由 + 上下文注入 + 配置覆盖"三层薄垫片**。全部改动点都落在现有接缝上（组消息、policy_rev 5s 缓存、tools 启用集解析、SQL scope）。

## 2. 数据模型（新增/迁移草案，全部幂等，沿用 db.js MIGRATIONS 风格）

```sql
-- 壳定义表 ★新增
CREATE TABLE IF NOT EXISTS shells (
  id INT AUTO_INCREMENT PRIMARY KEY,
  skey VARCHAR(32) UNIQUE NOT NULL,          -- 'code' | 'scm' | 'default'
  name VARCHAR(64) NOT NULL,
  description VARCHAR(255),
  persona JSON,                              -- 身份注入内容 {intro, tone, forbidden}
  domain_hosts JSON,                         -- 绑定域名列表 ['code.ronisyn.com']
  default_permission VARCHAR(8) DEFAULT 'write',
  default_preset VARCHAR(8) DEFAULT 'standard',
  model_policy JSON,                         -- {default_provider, default_model, temperature, budget_yuan, auto_bias}
  skills_allow JSON,                         -- 壳技能白名单（null=全部）
  status VARCHAR(10) DEFAULT 'enabled',      -- enabled | disabled
  created_at DATETIME DEFAULT NOW(),
  updated_at DATETIME DEFAULT NOW()
);

-- 壳级工具三态（无行=跟随全局；行=强制开/强制关）
CREATE TABLE IF NOT EXISTS shell_tools (
  shell_id INT NOT NULL, tool_name VARCHAR(64) NOT NULL,
  mode VARCHAR(8) NOT NULL,                  -- 'force_on' | 'force_off'
  PRIMARY KEY (shell_id, tool_name)
);

-- 壳级 settings 覆盖（复用 validateSetting；0.1 只覆盖允许集：default_models/systemPrompt?/护栏默认）
CREATE TABLE IF NOT EXISTS shell_settings (
  shell_id INT NOT NULL, skey VARCHAR(64) NOT NULL, svalue JSON,
  updated_at DATETIME DEFAULT NOW(),
  PRIMARY KEY (shell_id, skey)
);

-- 账号-壳关联（v1 单管理员=全壳可见；为企业多角色预留）
CREATE TABLE IF NOT EXISTS account_shells (
  account_id INT NOT NULL, shell_id INT NOT NULL, role VARCHAR(16) DEFAULT 'user',
  PRIMARY KEY (account_id, shell_id)
);

-- 渠道绑定（渠道账号/机器人 → 壳）
CREATE TABLE IF NOT EXISTS channel_bindings (
  id INT AUTO_INCREMENT PRIMARY KEY,
  channel VARCHAR(16) NOT NULL,              -- wechat | feishu
  external_key VARCHAR(128) NOT NULL,
  shell_id INT NOT NULL,
  UNIQUE KEY uq_channel_key (channel, external_key)
);

-- 存量表加列（幂等迁移）
ALTER TABLE conversations ADD COLUMN shell_id INT NULL;      -- NULL=默认壳
ALTER TABLE usage_stats   ADD COLUMN shell_id INT NULL;
ALTER TABLE audit_log     ADD COLUMN shell_id INT NULL;
ALTER TABLE scheduled_tasks ADD COLUMN shell_id INT NULL;
ALTER TABLE task_contracts  ADD COLUMN shell_id INT NULL;
ALTER TABLE knowledge ADD COLUMN shell_id INT NULL;          -- scope 增 'shell'
```

种子：`shells` 预置一行 `skey='default'`（persona=空 → 维持现状无身份，US7 回归锚点）；code 壳由克隆向导生成。

## 3. 关键机制设计

### 3.1 壳解析（入口路由）
- 新增 `resolveShell(req)`：优先 `x-shell` 头（nginx 按 server_name 注入）→ 回退 Host 匹配 `domain_hosts` → 回退默认壳；壳 disabled → 403 + 明确提示。
- 前端启动时 `GET /api/shell/me`：返回壳信息（品牌/模型策略/工具勾选影响由后端保证，前端只做展示与默认选中）。`POST /api/conversations` 未带 shell 时取当前解析壳；老客户端不带 → 默认壳（兼容）。
- nginx：每域名一个 `server_name`，全部 `proxy_pass` 到同一 upstream（880），透传 `Host`；SSE 保持 `proxy_buffering off`（模板现成）。

### 3.2 身份与上下文注入（复用 P13 三层接缝）
- 现有"身份/环境/纪律"三层 + 每轮快照的拼接点（`server/agent.js:164-212`：`ENV_IDENTITY(permission)`/`ENV_ENV`/`ENV_DISCIPLINE`，runAgent 内 `buildEnv()` 动态拼装；`server/index.js` 组消息处）：有壳且 persona 非空 → 身份层在现状中立措辞（agent.js:176「你是 RW 工作台智能体…」）基础上**追加壳人设语境与壳 AGENTS 摘要**；默认壳 persona 为空 → 身份层保持现状措辞不变（中立、无业务人设，与今日逐字一致）。
- 注入内容长度上限 + 占位符检疫（防 persona 注入攻击：persona 只作文本，含平台占位符文本时截断提示，沿用现有检疫工具）。

### 3.3 知识/技能按壳过滤
- kb 注入查询改为 `WHERE scope='global' OR (scope='shell' AND shell_id=?)`（默认壳只取 global，与现状一致）；kb_add 增 `scope='shell'` 选项（权限：需该壳会话）。
- 技能：`skills_list` 显示 全局 + `skills/<shell_key>/`（若存在壳目录）；`skill_load` 校验壳白名单（shells.skills_allow）。v0.1 壳技能目录= `RW_SKILLS` 下 `shells/<shell_key>/*`，发行物 apply-pack 可预置。

### 3.4 工具启用集（壳三态，即时生效）
- 解析顺序（现 execTool 前的新增一层，实现为纯函数可单测）：
  `平台豁免(4) > 壳 force_on > 壳 force_off > 账号启用集 > preset tier`
- 生效即时性：壳配置并入现有"5s 缓存 + policy_rev 版本"读取路径（壳配置变更 bump 版本 → 模型与执行面 5s 内可见新规则，机制现成）。
- 高危工具默认策略：克隆向导默认把 GUARDED_TOOLS 7 项设为 force_off（企业壳建议），可人工放开为"随权限/审批"。

### 3.5 文件与命令边界（壳工作区）
- 壳工作区 `/srv/rw-workspace/<shell_key>/`（v0.1：该目录只影响 read/write 会话的 limitPath——复用现有 `inside()` 双检；full 会话语义不变）。
- 壳级 env：模型 Key 仍全局（N6 最小化=v1 只保证"壳内不显示他壳不需要的 key 列表"，硬隔离留给方案 A）。

### 3.6 计量/审计/调度/契约（shell 维度）
- usage_stats.shell_id 由会话携带落库（runAgent ctx.shellId）；审计管理动作（建壳/克隆/改工具/启停）落 audit_log（action=`shell.*`）。
- scheduled_tasks / task_contracts 建单时记录发起会话的壳；driver 无人值守执行按契约壳取模型策略与工作区（`server/driver.js` 现有 ctx 组装点增两行）。
- 用量视图（docs/sql/usage_views.sql）追加 `v_usage_by_shell`。

### 3.7 渠道绑定（v0.1 简单化）
- `channel_bindings`：微信机器人/飞书应用 ID → 壳；未绑定 → 默认壳。会话创建（`server/channels/*.js`）改读绑定表替代硬编码默认（顺带修"渠道硬编码 deepseek"旧账：模型策略改读壳/会话配置）。

### 3.8 统一后台（同进程 admin 面）
- API：`GET/POST /api/shells`、`PATCH/DELETE /api/shells/:id`、`POST /api/shells/:id/clone`、`PUT /api/shells/:id/tools`、`GET /api/shells/:id/usage`、`POST /api/shells/:id/export`（instance-pack JSON）、`POST /api/shells/import`。
- UI：并入现有"设置"体系新增「壳管理」标签（admin 可见）；克隆向导 = 表单（身份/域名/工具矩阵/模型策略/知识范围）。
- instance-pack 结构 = shells 行 + shell_settings + shell_tools + 知识/技能引用清单 + 模型策略；供克隆与"升 A"复用。

### 3.9 升级路径（D → A 保留口）
- "升 A"= 把 instance-pack 交给现有发行物流水线（`scripts/apply-pack.mjs` + PROD-DEPLOY 模式）：独立目录/库/端口/env + 域名独立 upstream。壳配置与实例解耦后，A 只是"部署形态"，不再是"另一套设计"。

## 4. 安全与隔离（方案 D 逻辑隔离的强制项）

1. **集中化 scope 强制**：新增 DB helper `shellScope(shellId)` 统一拼 SQL 条件；会话/知识/任务/契约/统计查询全部经它（防漏 WHERE）。
2. 文件隔离：read/write 会话工作区路径按壳（3.5）。
3. 管理面角色：壳管理仅 admin；account_shells 使普通账号可见范围可控（v1 单管理员下全可见，不阻断）。
4. persona 文本进提示词前的长度/占位符检疫（3.2）。
5. 回归保护：默认壳路径任何行为不得改变（测试用例 TC-20 族兜底）。

## 5. 兼容与迁移

- 全部新增列允许 NULL；存量数据=默认壳视图不变（NULL → default）。
- 老 API 不带壳参数 → 默认壳语义；`/api/chat` 响应结构不变。
- 880 回归：selfcheck 12 项 + 22 项能力走查 + 渠道冒烟。

## 7. 方案 A 差异附录（若 D1 改选 A）

- shells 表降级为"每实例一份本地壳定义"；`account_shells` 无跨实例意义。
- 统一后台 = 独立轻量管理服务，通过各实例 admin API 或 pack 分发下发配置（v1 不实现跨实例实时管理，用 apply-pack 语义）。
- 域名路由：每壳独立 nginx upstream/端口/DB；故障隔离天然。
- 其余（persona 注入/知识/技能/工具三态/计量）机制相同，只是作用域=单实例。
- 推荐：无论 D/A，"壳配置包"格式先行统一（instance-pack），切换成本=部署层。

## 8. 未决与风险

- 风险1：逻辑隔离漏配 WHERE → 隔离测试（TC-13..15）设为发布门禁。
- 风险2：多壳共享进程的资源争抢 → 壳级预算 + 现有并发护栏；超限停用该壳任务而非全平台。
- 风险3：persona 注入使模型"以为自己是 X"→ 信任契约 C4 纪律不变（诚实层），persona 仅影响语境不影响"不得冒充所选模型"。
- 待决：D3 壳级代码形态；D4 账号体系；D5 数据边界；D6 默认壳归属（本方案默认壳=default）。
