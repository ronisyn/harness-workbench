## 1. 要解决的问题（现状证据）

- 现分流=全局白名单正则 `TOOL_INTENT_RE`（`server/index.js:288-292`）：命中→带全量工具；未命中→按纯问答，**漏判即静默降级（历史"假开始"根因之一，`docs/archive/诊断报告-三问题根因-20260905.md`）**；
- 与壳无关：所有壳共用一张正则，无法按壳收敛词表；
- 无任务类型概念、无危险度显式判定入口（高危目前靠 hooks/审批兜，但不形成"意图级"认知）。

## 2. v1 范围（用户认可：先窄后宽）

**识别输出= 三个低维标签之一**（不判任务类型——任务类型留给议题③）：
1. `要动手 · 普通` → 走工具链执行；
2. `要动手 · 高危`（命中高危词/动作：删除/生产/推送/清空/直接改库等）→ **先触发审批**，批准后执行；
3. `只读规划 / 讨论`（先别改/方案/评估/设计…）→ 只读工具面，承诺不改文件；
4. `闲聊/收尾`（未命中任何动作词）→ 纯对话，不带工具；
5. **兜底「拿不准就问」**：像要动手但词表/兜底都不确定 → 明说"要动手还是只讨论？"，**绝不假答应**。

## 3. v1 机制（两层，无 LLM 依赖）

```
① 每壳词表（随壳包 git 版本化）
   pack 新增可选节 intentRules = { do:[词/正则], highRisk:[…], readonly:[…], chatOnly:[…] }
   —— code 壳的词表 ≠ scm 壳 ≠ video 壳；默认壳保留系统级兜底清单（≈现 TOOL_INTENT_RE 迁移而来）
        ↓
② 意图回显（交互层，核心改动点）
   每次请求识别后，在回复上方灰字一行：
   「👆 我理解：要我动手·普通 → 将使用本壳工具链执行；若只想讨论请说明」
   识别错误当场可见 → 用户纠正即得样本（纠错回填词表 = intentSamples 的沉淀来源）
        ↓（可选，默认关，后置）
③ LLM 兜底：词表未命中且"像任务"时，一次小调用分类（kind=intent 入账，几分钱/次）；
   也不确定 → 走「拿不准就问」。默认关闭，真实数据够再开。
```

## 4. 与壳包 schema 的关系（v1.1 增补，非推翻 v1）

- 壳包新增可选节：`intentRules`（第 3 节）；`intentSamples`（纠错沉淀的例句库，**后置可选字段**，等壳真跑后用真实对话生成，见 ①收口 §3 schema 的 intent 扩展）。
- 意图回显出现在会话 UI；识别/回显结果进 audit/tool_calls 留痕。

## 5. 验证（考题集，随壳包 eval/ 版本化）

- 每壳 20-30 句考题（动手·普通/高危/只读/闲聊/拿不准 各若干），改词表/加壳先回放（同①的金标评测集同构）；
- 880 E2E：直接模式对话 10 句人工核对回显正确率；
- KPI 增一维：**假开始率**（识别为动手但零工具调用且声称完成的占比——现有"假继续"检测的正规化）。

## 6. 去留与衔接

- 作废/迁移：`TOOL_INTENT_RE` 语义拆入壳词表+默认壳兜底（行为迁移需回归：老会话正常问答不回归）；
- 衔接 ③：任务类型识别（修 bug/新功能/分析…）**不在 ②v1**，由③任务档案+路由按"任务画像"承接（用户指定或画像匹配）；
