# plugin-dev-intake（开发需求采集：插件）

适用：用户提出**插件开发/升级**需求时（A3 扩展中心「插件」资产线的 intake）。

1. 判定边界：硬动作（解析/生成/IO/算法）→ 插件；纯"教模型怎么做"→ 技能；带入口的成品 → 应用。拿不准先问。
2. 逐项采集（每项一句话，用户没答就追问，**不替用户编造**）：
   - **触发场景**：什么情况下要用到它？
   - **期望效果**：希望它做到什么？
   - **涉及壳**：哪些壳/还是全部（扩展中心装载）？
   - **代码动作类型**：新增工具？升级能力？修 bug？
3. 字段齐备（四字段全有）才算采集完成——齐判据，缺任一项不提交。
4. 调用 `intake_submit` 工具提交：`{ type:"plugin", scene, effect, shells, actionType }`。
5. 提交成功（返回 id）后告知用户：需求已记为**待审**，将在进化集审批台统一审批（采纳→立项）；不要自行开始写插件代码。
